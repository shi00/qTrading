## 3. 模型与场景

### 3.1 输入、状态与消费者

写入：`BaseDao._save_upsert` 成功执行后 → `WriteQuality.record_write` → `HealthCheckMixin.check_data_health` 将超阈值关键表纳入 `missing_critical`。

读取：`prepare_screening_context` 初始化/刷新等级并产生非空候选 → VM 注入 `context["data_processor"]` → 策略 `filter` 的 `require_quality` → `_check_tier` 优先取 required 表等级 → 策略结果。`BaseStrategy.check_dependencies` 判数据是否存在/为空，不替代覆盖率或质量裁决。

复权：按股票及日期排序 → factor 填充 → `first/last` 基准 → ratio/unknown 标记 → 指标/回测撮合。`ref="first"` 是回测基准；“基准不取期末”本身不是整个历史信息集已经 PIT 的证明。

| 场景 | 当前可核对行为 | 验证边界 |
| --- | --- | --- |
| processor 缺失/未初始化/等级不足 | 严格缺失抛错；未初始化按 0；等级不足始终拦截 | 主责静态全读；未运行 |
| E2E/非严格开关 | E2E 整体旁路并 warning；非严格仅放行缺 processor | `app_env.is_e2e_mode` 的冻结产物保护已读；bootstrap 未完整追查 |
| 关键表 CRITICAL，但最新日期新鲜 | 逐表 0 被覆盖为 3/2，门控读到被覆盖等级 | D06-F01 |
| 连续窗口、采样外股票、窗口边缘缺日 | 仅消费 `_scan_missing_dates`；不带调用窗口/采样覆盖证明 | D06-R01；fast-path 无深扫描不拦截是已声明行为 |
| Decimal / None / 合法零 | 只对推断为 decimal 的 object 列 cast；无 fill(0) | 依赖 infer_dtype/cast 未实测；不推断全空列已归一为 float |
| qfq 全空/基准零/合法恒等 | unknown 与 identity 分离；pandas ratio 的 None 两义必须另判 status | 主责明确；消费者覆盖不全，见 R03 |

| 脏日期、正常重写、24 小时过期 | 最近成功登记覆盖；过期返回 None，不触发该信号降级 | 时效是明确设计，不冒充持久数据已修复 |
| 未来公告/退市/尚未上市/行业变更 | 查询有 PIT 条件和存活片段；当前快照限制另列 | 仅局部 SQL，不宣称全历史正确 |
| 取消/失败/并发/重启 | gate 无 await；WriteQuality 用线程锁；扫描状态可被多次评估刷新 | 未做同步屏障或故障注入；取消后完整性见 R01/T01 |

| `vol` / block_trade | 万股 | BlockTradeStrategy 的 VWAP 本地约束及 snapshot fixture | 279 万股 → 27900 手 → 2.79 万手；误作 279 手会小 100 倍 |

`threshold_in_data_unit` 的可用尺度仅 yuan/wan_cny/million_cny/yi_cny；它是金额换算器，不支持 lot 或 thousand_cny。本轮未观察到以不支持单位调用它的真实入口，**不据此报缺陷**。pandas attrs 优先、LazyFrame 回退 declared_unit；未知单位抛 StrategyParamError。未确认 attrs 经过所有 concat/join/序列化后仍存在。数量同列无量纲比和明确的手→股换算不按“裸数值”机械误报。

缺失与零：None/NaN 不能等同合法 0；未知复权不能等同合法 ratio=1。当前 Decimal 工具没有补 0；qfq 的未知分支没有补 1；但引擎成交量窗口中 `fill_null/fill_nan(0)` 是独立消费者策略，不能从上述工具正确性推导该窗口缺失语义已获验证。

### D06-F01 · P2 · 已判 CRITICAL 的表被新鲜度等级覆盖，逐表门控绕过降级

- **类别/置信度**：defect / high；依据完整静态可达路径和 Python 字典赋值/最小值语义，不依赖未核验的 pandas/Polars 行为。Git 历史关系 unknown。
- **位置**：`data\mixins\health_mixin.py:HealthCheckMixin.check_data_health`（已读 401–741），`_classify_table_tier`；`data\persistence\quality_gate.py:_check_tier`；消费方 `PolarsBaseStrategy.filter`、`VolumeBreakoutStrategy`。
- **契约**：质量配置正本要求按 required 表真实等级判定，等级不足拦截；DAT-03 要求关键表脏写降级能阻断依赖它的策略。逐表独立判级不应覆盖同一表已经确定的 CRITICAL 事实。
- **真实可达输入**：stock_basic 具有 5000 只活跃股票，daily_quotes 仅覆盖其中 100 只，但含最新交易日；其余表正常。`CacheManager.check_comprehensive_health` 按 distinct(ts_code)/total_stocks 得到 0.02；这不是空数据场景。
- **逐跳证据**：
  1. `CacheManager.check_comprehensive_health` 的 `_check_single_table` 返回 ratio=0.02。
  2. 数据字典把 daily_quotes 标 critical；`check_data_health` 将 ratio<0.1 的它放入 `missing_critical`，全局 `_quality_tier=0`，并先写 `_quality_tier_by_table["daily_quotes"]=0`。
  3. 紧接着无条件赋值 `_quality_tier_by_table["daily_quotes"]=_classify_table_tier(lag_days=0)`，返回 3，覆盖前述 0。financial_reports 的单独赋值存在同类覆盖点，但本发现的可达例使用 daily_quotes，不假定财务覆盖守卫失效。
  4. `DataProcessor.prepare_screening_context` 即使看到全局 0 也只重查健康，不拒绝返回；100 只有效 close 形成非空 screening_data。
  5. `AIStreamMixin.run_strategy` 注入 dp 并调用 `strategy.filter`。VolumeBreakoutStrategy 要求 SILVER，继承 required_tables=("daily_quotes",)。
  6. `_check_tier` 用表字典得到 effective=3，而非全局 0，故进入策略逻辑；`check_dependencies` 仅检查数据存在。候选满足涨幅/换手率条件时可正常输出，实际关键表降级没有执行阻断。
- **实际/预期**：现为 health 红色且 global=0、同表 effective=3 并运行；预期该表应保持 0，策略 body 不执行、抛 QualityGateError。影响为部分采集/覆盖不足时以达标数据名义筛选；不声称所有输出必错，也不把 log 红色说成完全无提示。
- **反证**：严格开关不会覆盖 per-table 分支；非 E2E 可触发；非空数据避开依赖空表早退。检查 health 完整返回段没有后续修正。已读 coerce 测试仅断言 status/global=0，未断言表级值与实际策略拒绝。WriteQuality 降级也经过同一覆盖点，但不以人工注入无效主键日期证明其真实数据库可达。
- **最小方案**：在 `check_data_health` 构造逐表快照时，先分类普通表，再把 `missing_critical` 的 0 最后覆盖回去；或仅对不在该集合的表赋 classifier 结果。global/by_table 同轮产出，补查 run_quality_scan/fast-path 是否会保留旧表字典。**不推荐简单取 min(global, table)**，否则无关财务故障也会阻断健康的报价策略，破坏逐表隔离。
- **回归输入→期望**：覆盖 100/5000、报价新鲜 → daily_quotes=0，调用 VolumeBreakoutStrategy.filter 前门控抛错；覆盖正常、仅无关财务表不足 → 报价策略仍可运行；coerce 超阈值经健康检查 → 对应表=0，随后正常写入并重新检查才解除；保留未登记表回退/E2E/严格开关既有契约。

### D06-R01 · risk · 质量等级/窗口证据不是实际调用窗口的全量证明

`check_continuity` 使用**实际数据自身 min/max**圈定期望交易日；空输入 coverage=0、missing_count=0，无期望日 coverage=1 是当前定义。`run_quality_scan` 只扫随机样本一年，跳过无行情样本；缺日集合每次重置，取消可 break 后继续聚合；扫描只更新全局 tier，未在已读段同步重建逐表字典。`_check_tier` 仅消费集合，不拿调用区间、股票、扫描代次或失效时间。五个期望日仅有后三日时，数据自界定区间可能“零缺日”，不能证明五日需求满足。

这是覆盖证据边界，不把已文档化的代理/fast-path 行为重报为新缺陷。尚需真实策略窗口、采样选择、停牌/上市日历及并发刷新顺序闭环，才能区分合法缺日与错误放行。回归：采样外缺日、首尾缺日、全空一股、取消半扫、同 processor 重评估；期望“未核/不完整”不得冒充已验证完整，具体等级策略另需批准。D05/D07/D08/D22 承接。

### D06-R02 · risk · block_trade 输出同名 amount/vol 与固定展示单位冲突，尚缺实际依赖链实测

本地实现/注释约束声明 `BlockTradeStrategy._filter_logic` 保留大宗 amount/vol 原名、把 base 重名列变为 `_base`；本地 fixture 采用 amount 万元、vol 万股。PolarsBaseStrategy collect→pandas 后直接返回（该策略 AI=False）。VM 将结果提交为原始分页行；`_format_cell_value` → `format_metadata_cell` 只按列名固定 amount=千元、vol=手，且该两列不隐藏；`ReviewManager.save_results` 也读取原名，没有同时取 `_base`。因此存在跨层单位/语义冲突候选。

标准库数值反例：3500 万元正确 0.35 亿，按千元显示是 0.035 亿（格式化约 0.04 亿）；279 万股正确 2.79 万手，按手显示是 0.0279 万手（约 0.0 万手），相差 100 倍。现有 snapshot 测试只断言列存在及 close/pe/roe/行业值，未断言 amount/vol 来源和渲染；单位测试仅输入普通日线单位。

**未升级 defect**：未取得实际安装 Polars join/suffix/agg 的锁定版本源码或动态结果，未全读历史结果解码/展示链及上游接口单位；不把标准库算术冒充真实 Polars 复现。最小补证：原 fixture collect 后检查 amount/vol/amount_base/vol_base，再经过真实分页与格式化；同时核对落库快照。

若成立，推荐把大宗聚合显式命名为 block_amount_wan/block_vol_wanshare/block_vwap，保留 base amount/vol 的日线快照语义；为新列登记真实展示单位。另一方案是输出前统一换算并携带来源 metadata，但仍会把“全日成交”与“大宗成交”混在同名字段，故不优先。若存量已污染，先按 strategy_name/run_id 与原始 quote/block 表比对识别，不能无备份批量乘系数；全链确认、实施授权和数据修复分开。

### D06-R03 · risk · qfq 三态工具保护已存在，未覆盖所有消费者

`qfq_ratio_series` 对 unknown、identity 都返回 None；`TechnicalAnalysis._get_qfq_df` 已先用 status 区分并对 unknown 将价格置缺，AI history 摘要还有全空 close 早退。回测 `_apply_qfq` 对整列缺失也输出 ratio=null/unknown；portfolio 显式 ratio=None 拒绝成交，非有限/非正 ratio 也拒绝。

但 `_build_support_context` 仍仅判断 ratio is not None，否则使用原始价格/量；TechnicalAnalysis 缺 adj_factor **列**会原样返回。不能据此直接断言真实推荐错误：Oversold 的 RSI 主过滤对存在但全空因子已有排除保护，需证明独立预取历史与候选生成是否能产生不同因子状态；没有证明这一跳，因此不报确定缺陷。
