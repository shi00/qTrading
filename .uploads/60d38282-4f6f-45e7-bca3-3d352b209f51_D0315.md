## 2. 生命周期、配置与数据库

### D03-001 [P2] 停机只取消当前快照，没有关闭任务准入

**defect / high / confirmed；E-D03-001。**

- **触发与路径**：[SchedulerService](../../utils/scheduler_service.py) 的 `_on_job_missed` 自建 `_catchup_tasks`，在交易日历 await 后向 [TaskManager.submit_task](../../services/task_manager.py) 提交；[Shutdown](../../utils/shutdown.py) Step 0/1 先取消当前任务，再 stop scheduler。stop 不 drain misfire 子任务，submit 与延迟 `_enqueue` 也无 closing 闸门，故新 runner 可在取消快照之后启动，与 flush/dispose/线程池及 PG 关闭交错。更短反例是 submit 已返回 ID、enqueue 尚未 tick，空清单 cancel-all 返回后 callback 才启动。
- **反证与测试**：自动更新开关、组锁、unique_key、强引用及 APScheduler 自身 shutdown 均不能收敛自建 producer。[调度测试](../../tests/unit/test_scheduler_service.py) 只断言 shutdown/引用回收；[任务测试](../../tests/unit/test_task_manager.py) 只取消已登记任务，不覆盖 deferred enqueue。CON04 的底层不可中断债不是本项。
- **最小建议**：先在同一准入/占位边界关闭业务提交，enqueue 二次检查并释放本 owner；保留最后状态持久化通道。新增异步 scheduler 停止协议，停触发、取消并 drain misfire，再 cancel/join 已接纳任务、flush、dispose。允许重启时定义 reopening generation，拒绝旧 callback。
- **待运行验收**：日历 Event 阻塞期间进入真实停机，再释放；不得调用业务 factory、出现新活动任务或释放后写库。submit 未 tick 即停机的路径也须拒绝 callback，key 无残留、counter 归零。

### D03-002 [P3] ThreadPool reload 的第二次停机检查与 swap 不原子

**defect / high / confirmed；E-D03-002。影响限定为生命周期一致性和新池未关闭，不宣称已产生存活线程泄漏。**

- **路径**：[设置 VM](../../ui/viewmodels/system_settings_view_model.py) 在 IO worker 执行 [reload_config](../../utils/thread_pool.py)；二次 event=False 检查之后，shutdown 可设置 event、关闭旧池并清空引用，reload 随后又写回新池。访问因 event=True 拒绝，后续 shutdown 幂等早退，留下新池。
- **反证与测试**：GIL 不保证检查和两池 swap 原子；已有锁未用于两个入口。[线程池测试](../../tests/unit/utils/test_thread_pool.py) 在构造阶段置 event，覆盖二次检查之前，不覆盖之后。热重载旧池 `cancel_futures=False` 是批准契约。
- **建议/验收**：独立生命周期锁内重判、交换两池/尺寸；shutdown 同锁摘取引用，锁外关闭，避免 worker 自 join。barrier 卡在检查后、赋值前并发 shutdown，所有新池须关闭，两字段最终 None；保留 reload=False、真正 shutdown=True 的取消语义。

### D04-001 [P2] ASTOCK_CONFIG_FILE 使用相对文件名时所有保存失败

**defect / high / confirmed；E-D04-001。**

- **路径与影响**：[配置入口](../../utils/config_handler.py) 原样接受 `ASTOCK_CONFIG_FILE=prefs.json`；[storage._save_json_atomically](../../utils/config/storage.py) 在 try 前对 `dirname(path)` 调 makedirs，单文件名得到空字符串并抛错。save_config 返回 False，设置和 ensure_defaults 不能落盘；默认绝对路径不受影响。
- **反证/测试**：模板未限定绝对路径，入口未 resolve；filelock 不修复空 dirname。[配置测试](../../tests/unit/utils/test_config_handler.py) 使用带目录路径或替换原子保存函数，未覆盖单文件名。
- **建议/验收**：入口统一绝对路径，或 try 内仅对非空 parent 创建目录；保留同目录临时文件、fsync+replace，不吞 mkdir 失败。独立目录下保存、清缓存重读真实 JSON；覆盖子目录、Unicode/空格、不可写父目录，失败原件不变。

### D04-002 [P2] 诊断包无法序列化正常 AppTask 的 Message

**defect / high / confirmed；E-D04-002。**

- **路径与影响**：[设置诊断入口](../../ui/views/settings_tabs/system_tab.py) 或 [启动错误页](../../ui/startup_views.py) → [SystemDiagnosticsCollector.export](../../utils/diagnostics.py) 原样加入任务 name/description → JSON serializer 不支持正常 [Message](../../core/i18n.py)。[TaskManager](../../services/task_manager.py) 默认/运行/历史任务可带 Message，导出整个 ZIP 失败，不是仅缺一字段。
- **反证/测试**：[诊断测试](../../tests/unit/test_diagnostics.py) 任务替身全部用 str；numpy/datetime/Decimal 及未知类型测试不证明项目合法 Message 可用。
- **建议/验收**：构造任务列表时序列化稳定 `{key, params}`，params 递归脱敏，不用未经清洗 repr 或当前 locale 译文；未知对象仍 fail-fast，旧 str 兼容。真实 AppTask 的 QUEUED/RUNNING/历史 Message 与 str 一起导出，解 ZIP 可解析、key/params 保留、敏感值不出现。

### D04-003 [P2] 有界日志队列满时 stop_logging 未停止 listener 就关闭 handler

**defect / high / confirmed；E-D04-003。**

- **路径**：[logger](../../utils/logger.py) 使用容量 1000 的队列与原生 QueueListener。原报告核读本机 Python 3.13 标准库：stop 先 `put_nowait(sentinel)` 再 join；满队列先抛 Full。项目 finally 却关闭 handler、清全局引用，后续 QueueHandler 移除也被异常跳过，listener 仍持旧对象。
- **边界/测试**：普通运行期队列满尽力丢日志是已有取舍，不授权停机提前关 handler。[日志测试](../../tests/unit/test_logger_extended.py) 400 条且先 flush，不覆盖满队列或线程退出。
- **建议/验收**：关新记录准入，受控等待 sentinel 入队、join 确认结束后再关 handler/清引用；超时明确保留未停止状态并告警，不在事件循环无界阻塞。小容量满队列+阻塞 handler 并发 stop，释放后须退出、按顺序关闭、移除 QueueHandler；重复 stop 幂等，超时不假回收。

### D05-004 [P2] 原生 SQL 的 max_rows 可能在完整物化后才拒绝

**risk / high / unverified；E-D05-004；容量影响未测。**
