### 3.2 语料→训练指纹→发布的实际绑定

1. **采集**：源适配→清洗/例行过滤→按 source_kind 的近重复索引→SQLite `(source, source_id)` 幂等入库；既有 simhash 可重建索引。源码没有将所有新闻都认作 A 股的 CLI 补丁。采集时间参数仅巨潮消费，不把新浪 feed 的 start/end 当时间回放能力。
2. **标注/切分**：annotate 以 result.index 回填，丢弃非法项不会错位；label 为中文枚举，不能因 LABELS 元组顺序与训练不同就认定翻转。输出没保留完整事件元数据，离线 split 生产过程未随主责脚本闭环（F07）。训练只检查精确重复、稳定 id、精确 `(ts_code,publish_time)`；同集合重复、近重复、不同时间表示及时间顺序不在保证域。
3. **manifest**：规范 train/val/test；verify 拒绝额外 split_dev，避免训练优先读取 dev 与校验对象错位；实际非空行与实测 digest、manifest、sums 逐项交叉；新 tag 无 manifest fail-closed。legacy corpus-v1 登记行数且显性标未做 manifest。build 自一致性缺口另见 F06。
4. **指纹**：语料 sums 的字节 SHA256 + 六文件白名单逐文件 SHA256 + workflow 全文 SHA256 + HF 40位 revision + llama.cpp 40位 commit；canonical JSON 稳定。CLI 超参内联在 workflow，默认值在 train 源码，均在绑定域；model_version 不入是设计。语料实际下载 sha256sum + F2 sums锚 + manifest校验构成**预期**闭环，本轮未实际下载证明。
5. **source/config/pretrained digest 边界**：六脚本/workflow 是内容哈希；基座是 repo/revision 固定引用，不是本轮实测权重/config/tokenizer 的文件 digest；repo 名与下载选项由 workflow 哈希覆盖。训练摘要没有独立封存本地手工路径的全部输入 digest；因此**不能把 route 指纹当任意手工训练的溯源凭证**。runner/传递依赖等不入指纹的代价有批准说明及环境清单，不判漏覆盖缺陷。
6. **表示/效果双 Gate**：导出 bert pooler+classifier，encoder 为 model.bert；发布 f16，无 Q8 量化步骤。consistency 比较 encoder CLS，再把同一 head 作用两侧；不是独立 HF 分类器端到端效果复算。effect 消费该次 summary 与历史 note 的 F1，相比−0.03，首版只声明无基线。更换 corpus 时两套 F1 不等于同一 holdout 上公平退化试验；这是该门槛的解释边界，不擅改已批准公式。
7. **发布/消费**：顺序 gate 成功→最小 artifact→publish needs success→sha256复验→同tag拒绝覆盖→新Release；发布不checkout。模型/head/fingerprint 入 sums；tokenizer 不随包发布，how-to 指定从 note 的**固定 revision**取；不是任意下载 main。真实 header/张量、工具链兼容、tokenizer文件同一性仍需F10，魔数不是签名或格式全校验。

### D20-F01 · P2 · Gate 的分类头加载合同弱于实际消费者

- **位置/契约**：[verify_finbert_gguf.load_head_npz](../../scripts/verify_finbert_gguf.py) 对比 [news_sentiment_scorer.load_head_npz](../../services/news_sentiment_scorer.py)。消费合同要求 mode 为 linear/bert、labels 恰为 `[利空,中性,利好]`、四张量形状/有限性合法。
- **可达输入与链**：用户独立复验已有有效编码器，`--head` 给同shape、同数值但 labels 反序的 npz；`_parse_args→run_gate→load_head_npz` 仅读 mode/cw/cb/pw/pb，**完全不读 labels**；`apply_head→evaluate_criteria` 的全部数值与改前相同，原本能PASS的件仍PASS。该包送 runtime 时 labels 检查抛 ValueError，不能加载。`mode="mlp"` + 正确pw/pb也被门禁当非线性头接受，runtime拒绝。
- **影响/反证**：错误标注元数据的制品可得到PASS，却无法运行；没有证明发生现网反转或已发布坏包。当前workflow正常export固定标签/bert是保护，所以不是声称默认发布必坏；**不能覆盖用户手工复验入口**。既有 `test_load_head_npz_nonlinear_returns_pre` 还把 mlp 当成功fixture，是消费者合同漂移，不是保护。只有shape错误的测试不能证明标签受检。
- **最小修复**：只改该脚本 `load_head_npz`：with np.load(..., allow_pickle=False)；检查 mode 白名单、标签顺序、pre shape、各数组finite；保留现有三元组返回、linear/bert语义及阈值。不要为复用而引入带运行期配置/模型加载的service依赖。把旧mlp成功fixture改bert，再新增mlp拒绝断言。
- **回归 fixture→期望**：同shape标签反序/缺labels、mode=mlp、pre维度错、NaN均在后端加载前拒绝；正常linear/bert不变。对同一健康输入仅改labels，不得仍生成PASS。`python -m pytest tests\unit\scripts\test_verify_finbert_gguf.py -q`。
- **回退**：回退该函数及测试即可，无数据迁移；先别改阈值或重排已有权重。存量整包按元数据扫描识别，保留原包和sums，复验后另版发布，不原地换头。

### D20-F02 · P2 · `--tokenizer-mode direct` 不执行强制直连约束

- **位置/契约**：`verify_finbert_gguf._parse_args` 明示 direct=“强制内置分词器”；`run_gate`、`_verify_one_backend` 实际实现。
- **可达链**：CLI给合法模型路径并选direct，HF/llama原生token不匹配（脚本明确记录该FinBERT场景）→`fallback_used = not direct["match"] or mode=="fallback"` 仍True；token判据用fallback或match为True；向量计算始终走`_gguf_cls_via_hf_ids`。于是**强制直连测试的失败被自动fallback的成功替代**。
- **影响/反证**：显式调查原生分词兼容性的命令可能返回PASS，但没证明所选链能用。默认auto这样兜底是正确设计，workflow未传direct故不指称默认发布错误。reference不是外部缺失路径反例。
- **最小修复**：在 `run_gate` 独立分支解析三模式：auto才允许不匹配后兜底；fallback显式使用HF ids；direct不匹配应生成FAIL并非零，禁止把其token判据改True。direct完全匹配时两种ids本来相等，可以保留当前低层取向量实现；报告的输入模式/执行路径必须如实。保留CLI选项、阈值、auto/fallback兼容。
- **回归 fixture→期望**：以已有 `_patch_heavy` 风格固定不同token ids，direct→FAIL/1，auto→兜底且可PASS，fallback→明确兜底；各模式匹配输入保持通过；检查传给decode的ids与报告。`python -m pytest tests\unit\scripts\test_verify_finbert_gguf.py -q`。
- **回退**：恢复模式分支及测试；临时规避是不使用direct作为原生兼容证明，不能降低token门槛。

### D20-F03 · P2 · 只读统计在判断模式前已进入写库初始化

- **位置/契约**：`collect_corpus` 模块“只读统计，不写库”；`_run` 首句 `with CorpusStore(args.db)`；共享 `CorpusStore.__enter__→open`。

### D20-F04 · P2 · CLI 可以绕过每源最低请求间隔

### D20-F05 · P3 · 不均衡源的抽样名额不会补足

### D20-F06 · P3 · manifest build 可以成功写出自身 loader 拒绝的清单
