### 1. P2｜日序列统计对输入行顺序敏感

### 3. P2｜并发陈旧更新可以回退已完成的复盘

- **问题编号**：`PY-data.persistence.review_manager / DLP-RM-01`
- **代码位置**：[data\persistence\review_manager.py](../../data/persistence/review_manager.py)；[run_review](../../data/persistence/review_manager.py#L215-L513)，特别是 T5 未成熟暂存分支 383–410，以及 [_batch_update_results](../../data/persistence/review_manager.py#L1290-L1345)。
- **哪里有问题**：A 日更读取 T1_DONE 候选和尚缺 T5 的行情，随后等待指数/涨停价预取；期间 T5 行情补齐，B 回填同一记录并定稿。A 仍用旧快照写 `t5_pct=None、alpha=None、label=DRAW`。默认通用更新按 id 更新全部这些列，没有“不得回退已成熟值”的条件。预期 A 不应覆盖 B 已提交的 T5/标签/COMPLETED。路径为本文件读候选→预取 await→构造旧更新→通用更新；依赖的 [UPDATE 条件](../../data/persistence/daos/screener_dao.py#L1108-L1125) 已核实。
- **造成什么影响**：T5 收益、标签和状态可被清空/回退；统计和学习样本暂时消失，需要再次回填。不同 job 各建管理器，实例内锁不能解决。
- **原因**：三个复盘入口没有共享读—算—写协调；T1 回填的 NULL 守卫只保护该通路，通用更新必须允许补 T5，并不等于允许陈旧结果回退成熟记录。

**具体怎么改**

单事件循环应用内的最小控制是在本文件增加共享 loop-local 复盘周期锁，包围三个入口的**整个读—算—写周期**，而不是仅包写事务。可采用本文件新增的轻量装饰器：

```
from functools import wraps
from utils.loop_local import get_loop_local

def _serialize_review_cycle[**P, R](
    method: typing.Callable[P, typing.Awaitable[R]],
) -> typing.Callable[P, typing.Awaitable[R]]:
    @wraps(method)
    async def wrapped(*args: P.args, **kwargs: P.kwargs) -> R:
        async with get_loop_local("review_manager_cycle_lock", asyncio.Lock):
            return await method(*args, **kwargs)
    return wrapped
```

  在三个既有复盘入口的性能装饰器内侧应用此装饰器；保存快照和私有批写方法不另加同锁。接口影响：只使用已读的 loop-local API 和 asyncio.Lock，不反向依赖服务、不改公开参数/返回。边界验证：锁覆盖候选读取，跨管理器实例生效，排队取消自然传播；这些入口当前不互相调用，避免非重入锁嵌套。代价是整批序列化和等待时间；**不宣称保护跨进程/跨循环写入**，该场景应另行设计 DAO 条件写入，不能臆造当前不存在的 CAS API。

**如何验证**

前置条件：两个管理器、同一记录，A 在旧行情读取后由 Event 控制暂停，B 获得新 T5 数据；操作：并发调用日更/回填并控制交错；预期结果：最终 T5/alpha/COMPLETED 不回退，B 在 A 周期结束后重新读候选。补排队取消、异常释放锁及顺序正常三通路回归。现有 [guard_t1 SQL 用例](../../tests/integration/test_review_round_trip.py#L221-L258) 只验证单语句条件，没有上述真实交错；全部未执行。

### 4. P2｜指数窗口缺少有限正值检查

- **问题编号**：`PY-data.persistence.review_manager / DLP-RM-02`
- **代码位置**：[data\persistence\review_manager.py](../../data/persistence/review_manager.py)；[_index_window_return_pct](../../data/persistence/review_manager.py#L140-L143)、[_window_index_pct](../../data/persistence/review_manager.py#L1567-L1599)，由 [run_review 的 alpha 分类](../../data/persistence/review_manager.py#L463-L479) 消费。
- **哪里有问题**：指数预取/单条解析只排除 NULL，窗口函数只排除假值。非有限或负点位可以进入比值：两个无限端点产生 NaN；`index_pct is None` 不会拦截 NaN，alpha 成为 NaN，比较均不成立而落入 DRAW。负端点还能得到有限但荒谬的超额收益。预期非法指数点位应表示基准不可得，不定稿标签。
- **造成什么影响**：异常基准被伪装成已完成的复盘结果，污染标签或统计输入；不能以个股复权函数已有有限性守卫推断指数侧同样受保护。
- **原因**：个股侧守卫与指数侧守卫不对称，truthiness 不是数值有效性判断。已读[行级校验技术债](../../docs/debt/known-technical-debt.md#L699-L713)也没有提供保证数值必为合法点位的上游契约。

**具体怎么改**

在本文件纯函数入口归一端点并验证有限正值，同时检查计算结果；不更改百分点单位：

```
def _index_window_return_pct(
    idx_close_t0: float | None,
    idx_close_tn: float | None,
) -> float | None:
    if idx_close_t0 is None or idx_close_tn is None:
        return None
    try:
        start = float(idx_close_t0)
        end = float(idx_close_tn)
    except (TypeError, ValueError, OverflowError):
        return None
    if not (math.isfinite(start) and math.isfinite(end)):
        return None
    if start <= 0 or end <= 0:
        return None
    pct = (end / start - 1.0) * 100.0
    return pct if math.isfinite(pct) else None
```

  接口影响：仅使用本文件已导入的 math，沿用 `float | None` 结果语义、现有数值/标签解耦及百分数约定。边界验证：合法平盘仍为 0%，NULL、NaN、±Inf、零、负值及比值溢出均不产出标签；不把拒绝基准改为个股收益 0。脏缓存的可恢复性由下一项另行处理。

**如何验证**

前置条件：完整 T5 个股与脏指数端点；操作：运行纯函数及日更/回填路径；预期结果：`index_pct/alpha/label` 留 NULL，不为 DRAW/WIN/LOSS，数值收益仍可暂存。同时验证 `(3000,3180)` 仍为 6%。已读 [NaN 用例](../../tests/unit/test_review_manager.py#L1530-L1607)主要用只有 pct_chg 的替身，没有覆盖 open/close 为 Inf/负值；全部未执行，也未验证数据库对 NaN 的具体持久化行为。

### 7. P2｜写入失败仍向调用方报告正回填数

- **问题编号**：`PY-data.persistence.review_manager / DLP-RM-05`
- **代码位置**：[data\persistence\review_manager.py](../../data/persistence/review_manager.py)；[_batch_backfill_t5](../../data/persistence/review_manager.py#L962-L1007)、[_batch_finalize_labels](../../data/persistence/review_manager.py#L1009-L1053)、[_batch_update_results](../../data/persistence/review_manager.py#L1290-L1345)，以及 [T5 返回计数](../../data/persistence/review_manager.py#L779-L796) / [T1 返回计数](../../data/persistence/review_manager.py#L941-L945)。
- **哪里有问题**：已构造一条更新后，engine 不可用直接返回，或批事务失败且所有 fallback 也失败；上层仍按更新列表长度返回 1。真实 job 把此数呈现为“backfilled”。预期不能把零提交/已知失败计为已回填。
- **造成什么影响**：任务中心和日志宣称回填完成，实际仍缺收益/标签；T1 后续过期清理也无法依据返回路径识别前置回填故障。
- **原因**：私有写入 helpers 没有写入确认结果；父方法只数计划更新。已读测试明确接受 best-effort helper 的不抛行为，但没有验证该行为与公开“已回填数”承诺是否相容；**本发现不把 best-effort 本身判为缺陷**。

**具体怎么改**

最小安全选择是将**已知写入未完成**显式反馈，禁止返回正常成功计数。引擎不可用抛可分类的 RuntimeError；保留逐条继续尝试，但最终若有失败则抛出聚合失败。fallback 仍传已有 `conn`，使 DAO 普通错误不被自身无连接分支吞掉。以本文件 T5 fallback 为例：

```
if engine is None:
    raise RuntimeError("[Review] Engine unavailable for T+5 backfill")

failed = 0
for u in updates:
    try:
        async with engine.begin() as conn:
            await dao.backfill_t5_prediction(
                u["record_id"], u["t5_pct"], u["t5_price"],
                label=u.get("label"), index_pct=u.get("index_pct"),
                benchmark_code=u.get("benchmark_code"), alpha=u.get("alpha"),
                conn=conn,
            )
    except EngineDisposedError:
        raise
    except Exception as inner_e:
        failed += 1
        logger.error("[Review] Individual T+5 write failed: %s", safe_error(inner_e))
if failed:
    raise RuntimeError(f"[Review] {failed} T+5 writes did not complete")
```

  另外两 helper 同样调整，调用仍限现有接口；正常事务失败后才执行此 fallback。接口影响：不臆造 rowcount，R2/R5 原传播边界保留，异常内容只含计数/脱敏错误。边界验证：事务回滚后计数重新开始；部分成功不假称全成功；取消不能继续重试。**兼容性变化须明确**：原“失败仅日志”测试应更新，job 会收到失败而不呈现正数；若业务坚持非阻断返回，需先把公开结果改为成功/失败/未知的显式契约，不能继续谎报原整数。精确影响行数以及并发 NULL 守卫零行更新仍需 DAO 提供确认，当前 API 无该返回值，本片段只修复已知失败被计成功。

**如何验证**

前置条件：一条可计算候选，分别令 engine=None、批事务/fallback 全失败、部分 fallback 成功；操作：公开回填入口执行；预期结果：不返回正成功计数，job 不显示全部已回填，也不继续后置清理。全成功仍返回原值；EngineDisposedError/CancelledError 原样传播。已读 [batch 测试](../../tests/unit/test_review_manager.py#L3858-L3951)和[补标签 fallback 测试](../../tests/unit/test_review_manager.py#L1840-L1954)只直接调用 helper，没有闭合“故障→公开计数→任务呈现”；全部未执行。
