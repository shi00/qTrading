### 6. P2｜买入价缺失/非有限值没有按 invalid_price 跳过，可能中断整次撮合

- **问题编号**：`PY-strategies.backtest.portfolio / PORTFOLIO-01`
- **代码位置**：[strategies\backtest\portfolio.py](../../strategies/backtest/portfolio.py)；`_buy_to_target` 515–698、`_reallocate_unfilled_budget` 758–847；价格取值 `_exec_price` / `_exec_nominal_price`。
- **哪里有问题**：买入只检查 `raw_entry_price<=0 or qfq_entry_price<=0`。NaN 不满足该条件；有效 qfq_ratio 存在时，会进入 `int(target/raw_price/100)` 并抛 ValueError。NULL 执行价格则在 `float(None)` 时提前抛 TypeError，连跳过 guard 都未到达。补分配复制相同检查。
- **可达证据**：空持仓+有效信号/预算 → process_day/rebalance 生成买入目标 → 单行报价执行价 NaN、显式 ratio=1 → 两个 `<=0` 均 False → `_qfq_ratio` 得 1 → int(NaN) 抛错。不依赖成本模型即可定位。NULL 经行情归一后可出现，实际数据频率未知但模块明确承诺损坏价格跳过。
- **造成什么影响**：一只坏报价使整个调仓函数异常，而不是记录一个 `invalid_price` 并继续其他股票；本项不声称本次运行实测失败。
- **原因**：卖出已采用 `math.isfinite`，买入保护没有同等完整性。

**具体怎么改**

仅本文件两个买入入口在读取执行价格的窄边界处理 TypeError/ValueError，并在取整前验证 raw/qfq 均有限且正；主遍记录 invalid_price，补分配跳过坏报价。复用已有 math，不以 0 代替未知报价；不改变公开 float helper 的全局语义。接口影响：与现有零价 skip/缺 ratio 契约一致，正常费用/整手计算不变；边界验证：NULL、NaN、±Infinity、非正价、valid ratio/缺 ratio、多股票并行目标、补分配分别验证，无坏股成交且好股继续。已有持仓的估值缺价是另一路径，不能声称此局部修复解决全部 NULL NAV。
  主遍中的以下片段置于停牌检查后、涨停比较前，替代靠后的价格读取/非正检查；这样限价比较也不会先触发 `float(None)`，之后比较可使用已验证的 `raw_entry_price`。

```

    qfq_entry_price = self._exec_price(quote)
except (TypeError, ValueError):
    _record_skip(ts_code, "invalid_price", 0)
    continue
if not (
    math.isfinite(raw_entry_price)
    and math.isfinite(qfq_entry_price)
    and raw_entry_price > 0

up_price = quote.select("limit_up_price").item() if "limit_up_price" in quote.columns else None

        continue
```

  补分配没有 `_record_skip` 局部函数，不能跨作用域调用它；在该方法停牌检查之后、涨停比较之前使用同样价格保护，并令后续涨停比较采用已验证 raw 价：

```

    qfq_entry_price = self._exec_price(quote)
except (TypeError, ValueError):
    continue
if not (
    math.isfinite(raw_entry_price)
    and math.isfinite(qfq_entry_price)
    and raw_entry_price > 0
    and qfq_entry_price > 0
):
    continue
up_price = quote.select("limit_up_price").item() if "limit_up_price" in quote.columns else None
if up_price is not None and not self.config.allow_limit_up_buy:
    if raw_entry_price >= float(up_price) - 1e-6:

```

  接口兼容说明：两段均嵌入现有 for 循环，不新增公共 helper；正常整手、成本、缺 ratio 理由及补分配跳过行为保持。两轮校验如上；没有修复/认证另一路已有持仓 NAV 缺价风险。

```

def _on_task_terminal(self, tasks) -> None:
    task = next((t for t in tasks if t.id == self._task_id), None)
    if task is None or not self._state.is_running:
        return
    if task.status not in (TaskStatus.CANCELLED, TaskStatus.FAILED, TaskStatus.INTERRUPTED):
        return
    cancelled = task.status is TaskStatus.CANCELLED
    self._task_id = None
    self._set_state(
        is_running=False,
        progress=0.0,
        progress_message=None,
        status_message=Message("backtest_cancelled" if cancelled else "backtest_failed"),
        status_color="warning" if cancelled else "error",
    )

# __init__ 完成现有state/notifier初始化之后
self._task_terminal_callback = self._on_task_terminal
self._task_manager.subscribe(self._task_terminal_callback)

# dispose 的统一清理之前
self._task_manager.unsubscribe(self._task_terminal_callback)
```
