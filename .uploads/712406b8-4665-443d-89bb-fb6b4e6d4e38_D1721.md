##### D20-001｜P2｜畸形模型字段未经脱敏进入普通日志

- **触发/逐跳证据**：统一个股分析 `_execute_scenario_analysis` → `_validate_analysis_output` 解析供应商 JSON → [`validate_ai_analysis_response`](../../services/ai_service/output.py#L55) 的非法 score/confidence/recommendation/conclusion_label 分支直接把原值传给 logger（L74、L90、L107、L124）。供应商返回非数值字符串并包含个人信息时，校验虽将字段置 `None`，原内容已写日志。旧链 `StockAnalysisService.analyze_stock` 亦在 L735 调用同一校验器。
- **影响/契约**：坏输出造成不必要的个人信息/敏感片段日志传播；违反 R9 与 ai-review SAFE-05，不是“输出被置空即可安全”。无需输入获得执行权，未声称远端实际泄露已发生。
- **反证**：[`_SanitizingFormatter.format`](../../utils/logger.py#L85) 只清洗 `exc_text`；普通 message 原样格式化。`JSONFormatter` L138 使用 `record.getMessage()`。这些 warning 没有 `exc_info`，全局异常脱敏不能兜底。已有输入 PII 中和不能保证非确定性模型不生成/回显个人信息。
- **最小改法**：仅改输出校验器的原值日志参数：记录类型/字段名，必要摘要经 `DataSanitizer.sanitize_error`；不要为修此问题改整个 logger 或删除诊断。
- **回归验收**：对 score/confidence/两种结论字段分别注入合成个人信息、已注册合成 secret 与 URL userinfo；捕获普通文本/JSON handler，断言原片段不出现、字段仍为 `None`；有效 0/正常标签保持。测试未运行。
- **旧债对账**：`P2-REV06-LLMOutput-SchemaValidation` 是完整 schema 缺口，不覆盖本项日志输出点；本项单独归属 D20，不在 D13 重复计数。

##### D20-002｜P3｜合法 JSON 非对象损坏行使全部审计聚合清空

- **入口/触发**：数据出口面板 [`EgressAuditViewModel.load_aggregates`](../../ui/viewmodels/egress_audit_view_model.py#L57) → `EgressAudit.get_aggregates` → [`_scan_aggregates`](../../utils/egress_audit.py#L297)。JSONL 含一条 `[]`、`null` 或数字，`json.loads` 成功，随后 `.get` 抛 `AttributeError`；行内捕获只有 ValueError/KeyError/TypeError。
