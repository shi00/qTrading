### 1. P2｜导航回调捕获旧页面状态，后续切换可能判断错误

- **问题编号**：`PY-ui.app_layout / APP-F1`
- **代码位置**：[ui\app_layout.py](../../ui/app_layout.py)；[`AppLayout._apply_navigate` / `_setup_navigate` / `_do_tab_switch`](../../ui/app_layout.py)。
- **哪里有问题**：挂载初始 MARKET；`dependencies=[]` 只注册一次 `_on_navigate`，其调度的 `_apply_navigate` 和 `_do_tab_switch` 捕获初始 current_tab。经导航切到 SCREENER 后发送合法 `market`，`_apply_navigate` 仍与初始 MARKET 比较并 return，界面不返回行情。仅删除这一 return 也不完整：旧 `_do_tab_switch` 仍因 `new_tab != current_tab` 为 false 不 set。已读 same-tab 测试只在初始 MARKET 测 MARKET，未覆盖先切走再回来。
- **造成什么影响**：任何目标为初始 tab 的合法导航消息可失效，用户无法经该协议返回行情。
- **原因**：订阅闭包读取旧快照，违反导航协议“订阅 handler 禁止读取 state 当前值作判断”。

**具体怎么改**

采用本文件已有 ref 模式保存最新 UI tab，不从长期订阅闭包读取旧 `current_tab`。以下为 `AppLayout` 内新增 ref 和 `_do_tab_switch` 的替换片段：

```
current_tab_ref = ft.use_ref(lambda: current_tab)
current_tab_ref.current = current_tab

async def _do_tab_switch(new_tab: int) -> None:
    try:
        await asyncio.sleep(DEBOUNCE_MS / 1000)
    except asyncio.CancelledError:
        raise
    latest_tab = current_tab_ref.current
    assert latest_tab is not None
    if new_tab == int(latest_tab):
        return
    target = NavTabs(new_tab)
    UILogger.log_action("AppLayout", "Navigate", f"tab={target.name.lower()}")
    current_tab_ref.current = target
    set_current_tab(target)
```

  `_apply_navigate` 保留前面的 settings/screener/backtest 序号逻辑，其末尾旧 `current_tab` 判断改为下列局部分支；必须同时修两个捕获点：

```
latest_tab = current_tab_ref.current
assert latest_tab is not None
if target_tab == int(latest_tab):
    return
await _do_tab_switch(target_tab)
```

  规范轮：ref/`run_task` 均为本文件现有模式，PubSub 线程仍只解析，setter 只在 loop 内调用。对抗轮：ref 在提交 tab 时立即更新，检查先切走再返回、重复深链 seq、同页不重复日志、取消传播及卸载竞态。兼容性：公开导航协议和组件签名不变；不把本片段当作 APP-R1 防抖或 APP-R3 通知线程风险已经解决。片段未实施、未运行。

**如何验证**

前置条件：保留挂载时 handler，操作：screener→market 两条消息各 await 并重渲染，预期结果：最后 rail/页可见状态是 MARKET；同页 settings:data 的 seq 连续递增、backtest prefill 不丢失。未运行。

### 2. P2｜取消设置保存后，saving 状态不复位

- **问题编号**：`PY-ui.viewmodels.ai_brain_settings_view_model / UIB-AIBRAIN-01`
- **代码位置**：[ui\viewmodels\ai_brain_settings_view_model.py](../../ui/viewmodels/ai_brain_settings_view_model.py)；[save_ai_settings](../../ui/viewmodels/ai_brain_settings_view_model.py)的SAVE_SAVING、CancelledError分支；[View保存处理](../../ui/views/settings_tabs/ai_brain_tab.py)亦只重新抛取消。
- **哪里有问题**：合法草稿进入SAVE_SAVING→线程池等待或reload被取消→直接raise而无状态恢复；同一仍存活VM之后任何保存均被重复提交守卫拒绝。setter在SAVE_SAVING期间也保持该状态，不能恢复。
- **造成什么影响**：用户需重建视图/VM才能再次保存，取消一次操作会阻断后续合法保存。
- **原因**：取消传播正确，但缺少结束/恢复保存状态的生命周期清理。已反证：正常失败路径设ERROR，草稿版本机制并不能修复取消分支；已读取消测试只断言异常不检查后置状态。

**具体怎么改**

仅本模块协调保存任务与取消清理：保存占用必须在真实持久化阶段结束后释放，取消时保留未确认版本并进入非saving的错误/待恢复反馈，再传播CancelledError。不建议裸finally立即解锁：[run_async](../../utils/thread_pool.py)取消等待不会停止正在写盘的线程；可持有本模块写入task并shield/收束后再释放，防并发第二次写。接口影响：R2、R16与接口bool/五字段原子保存保持，saved_revision不得伪成功；边界验证：取消写前、写中、已写后reload中和再次取消，确保无永久锁定、不宣称未写入、不让旧写覆盖新写。

  所属[save_ai_settings](../../ui/viewmodels/ai_brain_settings_view_model.py)关键建议片段：五个草稿值及captured_revision仍在原来的无await同步段捕获；把已有持久化与重载两阶段纳入本模块持有的operation。正常success/False及版本确认分支原样保留。取消只取消外层等待，operation完成回调才释放占用，避免立即finally解锁却留下写线程。以下不是已实施修复。

```
async def _persist_and_reload() -> bool:
    success = await ThreadPoolManager().run_async(
        TaskType.IO, _save_configs_sync
    )
    if success:
        from services.ai_service import AIService

        await AIService().reload_config()
    return bool(success)

def _settle_cancelled_operation(task: asyncio.Task[bool]) -> None:
    if not task.cancelled():
        failure = task.exception()
        if isinstance(failure, Exception):
            from utils.error_classifier import classify_error, classify_severity

            info = classify_error(failure, context="general")
            severity = classify_severity(failure, context="general")
            log = logger.critical if severity == "system" else logger.error
            log(
                "[AIBrainSettingsVM] cancelled save settled (%s): %s",
                info["code"],
                DataSanitizer.sanitize_error(failure),
            )
    self._set_state(save_state=SAVE_ERROR, warning_message="")

operation = asyncio.create_task(_persist_and_reload())
try:
    success = await asyncio.shield(operation)
    # 这里保留原有False、SAVE_SUCCESS及SAVE_STALE分支。
except asyncio.CancelledError:
    operation.add_done_callback(_settle_cancelled_operation)
    raise
```

  两轮补充校验：① 使用既有线程池、服务重载、状态常量与分类接口；不改公开签名，不更新取消保存的saved_revision，ERROR只表示没有向用户完成确认、不声称未写盘。② operation在写入/重载未完成时仍占用SAVE_SAVING，原外层取消及再次取消立即传播，完成回调消费异常并恢复状态；后发保存不会与尚未收束操作重叠。完整实施还须验证operation在应用关闭期间的强引用/收束；这里未执行任务，也不把建议片段等同于已验证修复。

**如何验证**

Given合法草稿及可控写入/重载屏障，When取消并等待收束，Then取消向调用方传播、状态不永久saving；之后一次保存可成功且版本确认准确。未运行，原因是本轮只读验证边界。

### 3. P2｜审计记录尚未读取或读取失败，被显示为零次外发

- **问题编号**：`PY-ui.views.settings_tabs.ai_brain_tab / UIV-AI-01`
- **代码位置**：[ui\views\settings_tabs\ai_brain_tab.py](../../ui/views/settings_tabs/ai_brain_tab.py)；[`AIBrainTab._build_egress_table` 与 card_egress](../../ui/views/settings_tabs/ai_brain_tab.py)。

  在本文件原 `_build_egress_table` 的空 rows 判定前插入：


  兼容性：`loaded` 已是公开 state 字段；`ds_not_checked` 中英文 key 已静态核实，语义为“未检查”，此处先复用，不宣称能区分正在加载与加载失败；未改 VM、外发行为或本函数返回类型。

**如何验证**

前置条件：loaded=False 且 rows=()/count=0，操作：渲染，预期结果：不显示“No egress records/0 次”作为已确认事实；loaded=True/空记录则正常显示；未运行。
