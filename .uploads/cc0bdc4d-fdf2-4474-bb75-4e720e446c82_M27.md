### 1. P2｜显式禁用联合情绪复用仍返回复用成功

- **问题编号**：`PY-services.ai_service.news_classifier / S-NCLASS-01`
- **代码位置**：[services\ai_service\news_classifier.py](../../services/ai_service/news_classifier.py)；[_classify_dedicated 的 reuse_bundled 分支](../../services/ai_service/news_classifier.py)。
- **哪里有问题**：SentimentSubRouteConfig 允许 `reuse_bundled_sentiment=False`；主题返回合法 Positive、专用情绪链整体 unavailable 时，代码只判断失败种类和枚举，没有读取该开关，仍返回 sentiment=Positive、status=success、source=reuse_bundled。

**具体怎么改**

仅在本模块复用条件中核对子路由开关；显式 False 必须禁止复用，缺键保持 schema 默认 True 的读兼容，类型异常不得按字符串 truthiness 放行。
  关键片段：替换 `_classify_dedicated` 现有复用 `elif`；前面的情绪成功分支与后面的 None/unavailable 分支保留。

```
elif (
    sentiment_route.get("reuse_bundled_sentiment", True) is True
    and self._sentiment_failure_kind(sentiment_error) == "unavailable"
    and bundled_sentiment in _SENTIMENT_ENUM

    result["sentiment"] = bundled_sentiment
    result["sentiment_status"] = "success"
    result["sentiment_source"] = "reuse_bundled"
```

- **接口兼容**：公开返回字段和缺键默认 True 不变；明确 False/畸形非 bool 值不放行复用，不改变已有独立任务执行次数。真实拒绝是否允许复用的未决政策仍另列风险。
- **兼容性检查**：不改变 bundled 模式、公开返回结构和 schema，不给模型字段控制程序策略。
- **回归检查**：True/False/缺键 × unavailable/invalid_output × 合法/缺失联合情绪矩阵；False 时保留主题但情绪 None，不能触发额外主题调用。

**如何验证**

- **代码位置**：[services\ai_service\news_risk.py](../../services/ai_service/news_risk.py)；[analyze_news_risk 旧链 cloud 成功分支 / _cloud_model_id](../../services/ai_service/news_risk.py)。

- **兼容性检查**：不改返回 DTO、冻结 dispatch、证据校验或新链 actual_model 优先级；保留缺元数据的兼容显示，不伪造新身份。

### 5. P2｜bert 分类头可把非有限特征洗成合法分数

- **问题编号**：`PY-services.news_sentiment_scorer / NSS-01`
- **代码位置**：[services\news_sentiment_scorer.py](../../services/news_sentiment_scorer.py)；[apply_head_and_score](../../services/news_sentiment_scorer.py)。
- **哪里有问题**：该函数承诺“单行特征含非有限值→None”，实际仅检查最后的概率。bert 路径先 tanh，Inf 可变为 ±1。可达反例：一行特征全为 +Inf、合法有限 pw 全为 1、pb/cw/cb 全为 0，尺寸与标签正确 → 预激活 +Inf → tanh 为 1 → logits 为 0 → 概率有限 → 返回合法标签、confidence 与 score，而非 None。无需假设模型质量或执行外部代码即可定位该纯函数反例。
- **造成什么影响**：原生异常数值被展示成可信情绪，违反 R21；只影响当前展示边界，不声称进入选股排序。
- **原因**：仅检查最终概率，没有保存原始特征的有限性；tanh 之后的 softmax 校验不能替代输入校验。

**具体怎么改**

仅在本函数预激活前保存原始行有限性，循环中联合判定：

```
valid_features = np.isfinite(features).all(axis=1)
# 保留既有头计算。
for row_index, p in enumerate(probs):
    if not valid_features[row_index] or not np.all(np.isfinite(p)):
        results.append(None)
        continue
    # 保留既有有效输出构造。
```

  接口影响：保留输入形状、等长结果与标签序，不填业务合法默认值；接口签名及 list[dict | None] 返回类型不变，无 schema 迁移。边界验证：同时覆盖 linear/bert 的 NaN、±Inf、正常行和有限输入但计算溢出的情况。不是“所有正常 score=0 都有错”。未实施、未运行。

**如何验证**

前置条件：上述有限 bert 头与混合正常/Inf 行，操作：应用分类头，预期结果：Inf 行 None、正常行不变、列表长度不变。现有 [Inf 测试](../../tests/unit/test_news_sentiment_scorer.py)只使用 linear 头，无法阻止 tanh 洗白。未运行；R21 尚无独立会话复核。

### 6. P2｜启动取消路径同步等待持有 join 的 worker 锁

- **问题编号**：`PY-services.news_sentiment_scorer / NSS-02`
- **代码位置**：[services\news_sentiment_scorer.py](../../services/news_sentiment_scorer.py)；[score_for_connection / _quarantine_worker / _ensure_worker_impl / _shutdown_worker_locked](../../services/news_sentiment_scorer.py)。
- **哪里有问题**：IO 线程在换产物时持 `_worker_lock` 做长进程清理；取消外层 await 不停该线程；启动取消分支在 loop 上同步取同一锁以 quarantine，导致整个 loop 等待多秒。与对话 worker 是同型风险，但本报告的证据和修复只属于本文件。
- **造成什么影响**：取消传播及新闻/UI 心跳被阻塞。
- **原因**：短状态与阻塞生命周期操作共锁。

**具体怎么改**

仅在本模块拆分短状态/隔离意图与生命周期长锁，清理继续以被跟踪任务 offload 并核对 generation；不得直接移除所有同步保护。本文件关键分支如下，初始化片段放在 `__init__`，方法片段替换本类取消标记方法：

```
self._quarantine_lock = threading.Lock()
self._quarantined_generations: set[int] = set()

def _quarantine_worker(self, generation: int) -> None:
    with self._quarantine_lock:
        self._quarantined_generations.add(generation)
        if generation == self._worker_generation:
            self._worker_state = "quarantined"
    self._spawn_cleanup_task(generation)
```

  在 `_ensure_worker_impl` 原生命周期锁内、计算 worker_stat 后，用短锁原子保护复用判定：

```
with self._quarantine_lock:
    if (
        self._worker_proc is not None
        and self._worker_proc.is_alive()
        and self._worker_ready
        and self._model_path == model_path
        and self._worker_stat == worker_stat
        and self._core_signature == signature
        and self._worker_state != "quarantined"
        and self._worker_generation not in self._quarantined_generations
    ):
        return True
```

  这不是完整 diff：本文件 `_ensure_ready` 的头复用入口同样要检查隔离意图；其余 generation/状态写入统一受短锁保护，清理确认成功后才移除对应代的意图，失败保留。保留已存在的清理任务与 generation 参数守卫；取消同步启动需收编实际 spawn 的代际，不能以过时代号承诺清理完成。锁顺序只允许生命周期锁→短锁，短锁内不做 join、队列 IO 或等待长锁。

  接口影响：已核对本文件现有 helper 签名与 threading.Lock，保留请求配对、同 loop 串行、取消重抛与 unavailable/partial 契约，无跨模块新 API。边界验证：核对旧代清理迟到、新代 spawn、正在 put/ready/打分的取消和全部快路径；不能只删除原锁而留下可复用窗口。外部签名不变；联动后需行为测试验证，未实施或运行。

**如何验证**

前置条件：真正的 ensure 线程已锁内暂停旧 worker 清理，操作：取消统一入口，预期结果：loop 心跳不等待该锁；放行后新代可继续。现有启动取消测试 mock 掉 ensure/stop，不覆盖真实锁争用。未运行。

### 8. P2｜新闻中的指数代码被误识别为同号码股票

- **问题编号**：`PY-ui.components.news_feed / NF-F1`
- **代码位置**：[ui\components\news_feed.py](../../ui/components/news_feed.py)；[`_STOCK_CODE_RE` / `_extract_stock_codes` / `_build_news_item`](../../ui/components/news_feed.py)。
- **哪里有问题**：正文如“上证指数 SH000001”→正则只保留六位 `000001`→它在股票 symbol 集合（测试也包含该 symbol）→生成“查看个股(000001)”→[HomeView._on_view_stock](../../ui/views/home_view.py)广播 screener:000001。仓库[指数定义](../../data/constants.py)明确 000001.SH 是上证指数，[测试](../../tests/unit/ui/components/test_news_insight_panel.py)也以 000001.SZ/平安银行为股票；两者不是同一对象。
- **造成什么影响**：强标记实际指向指数/不同交易所对象时仍产生个股跳转，错把新闻对象关联给股票。
- **原因**：交易所标记被丢弃，只校验 bare symbol。

**具体怎么改**

本模块保留正则交易所身份，并新增可选完整股票 ts_code 集合校验；以下为正则与提取器的替换，不硬编码交易所数字号段：

```
_STOCK_CODE_RE = re.compile(
    r"(?<![A-Za-z0-9])(?P<prefix_exchange>SH|SZ|BJ)"
    r"(?P<prefix_code>\d{6})(?!\d)"
    r"|[（(]\s*(?:(?P<bracket_exchange>SH|SZ|BJ)\s*)?"
    r"(?P<bracket_code>\d{6})\s*[）)]",
    re.IGNORECASE,
)

def _extract_stock_codes(
    content: str,
    valid_codes: frozenset[str] | None = None,
    *,
    valid_ts_codes: frozenset[str] | None = None,
) -> list[str]:
    if not content or not valid_codes:
        return []
    identities = frozenset(value.upper() for value in (valid_ts_codes or ()))
    codes: list[str] = []
    seen: set[str] = set()
    for match in _STOCK_CODE_RE.finditer(content):
        code = match.group("prefix_code") or match.group("bracket_code")
        exchange = match.group("prefix_exchange") or match.group("bracket_exchange")
        if not code or code not in valid_codes or code in seen:
            continue
        if exchange and f"{code}.{exchange.upper()}" not in identities:
            continue
        seen.add(code)
        codes.append(code)
    return codes
```

  在本文件 `NewsFeed`、`_build_news_controls`、`_build_news_item` 的原有参数之后，均追加 keyword-only `valid_stock_ts_codes: frozenset[str] | None = None`，逐层透传。`_build_news_item` 的原提取调用替换为：

```
stock_codes = _extract_stock_codes(
    content,
    valid_stock_codes,
    valid_ts_codes=valid_stock_ts_codes,
```
