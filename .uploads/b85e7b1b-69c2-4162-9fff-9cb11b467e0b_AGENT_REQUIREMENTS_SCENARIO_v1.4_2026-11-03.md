## 1. 阅读约定与不变范围

本文按“用户为什么来、带来什么、如何推进、获得什么、出错怎么办”重写需求组织。F01—F36、BR01—BR19、RR01—RR05、D01—D10、AC01—AC41 保留原编号，不删功能，不把支撑能力误当用户目标。

各场景写明用户旅程；F 条目定义相应能力；跨场景规则、参数和验收在后文统一约束。功能与约束稿承载完整细则，本文的F入口只定位定义，不重复一套规范。全文不替代上位 [用户需求](../USER_REQUIREMENTS.md)、[项目宪法](../../CLAUDE.md)或现行 ADR。

### 1.1 证据状态

- 主要对象是自主决策的个人投资者，次要对象是有明确方法的个人量化研究者。
- 用户需要减少资料整理、工具切换和反复解释的负担，但保留最终判断权。
- 以下场景来自用户需求正本与既有 Agent 基线，是设计和验证假设，不是访谈确认的高频排行。
- “比较研究”是复杂工作过程样例，不代表已证实的最高频场景；候选发现、资讯提炼、第二意见和跨期续研各有独立成果判据，不能只用比较报告代替验收。
- 原型演示、结构检查、真实运行时实验和产品验收分别记录，不能互相代替。

### 1.2 本次显式调整的是技术绑定，不是用户行为

工程方向、版本/API/存储和取证以[详细设计 §1—§4](./AGENT_DETAILED_DESIGN_v1.4_2026-11-03.md#1-完整harness优先的选型决定)为准；技术选择不改变产品行为、统一治理、单层委派及权限边界。

## 2. S00：首次准备，不要求用户成为 Agent 工程师

**用户目标：** 使用已配置模型和产品默认能力开始研究；有需要时再配置 Skill/MCP，而不是先搭建工作流。

**正常旅程：**

1. 用户能识别哪些模型已配置、是否可用，以及新执行使用哪个模型。
2. 零自定义 Prompt 时也有默认角色与业务模板，教程可从配置处直接打开。
3. 按需导入 Skill、配置 MCP；保存、连接成功、工具获准和实际可调用分别表达。
4. 修改、取消、恢复默认和升级都不会静默丢失用户已有内容。

**异常旅程：** 未配置模型只阻止需要模型的新执行，不阻止历史、搜索、复制和教程；安装/更新失败保留旧有效版本，缺依赖不自动安装或执行脚本。

**首次可见价值：** 有有效模型和足够资料时，用户可直接完成 S01/S04/S05 的小任务，不要求先配置 Skill/MCP 或修改 Prompt。问题、对象、时点或判据不清时只澄清影响结果的部分；资料不足指向原业务入口或明确的补充项，不要求用户理解内部任务图，也不暗中同步数据、安装工具或切换模型。

## 3. S01：快速理解与连续追问

**用户示例：** “利润增长但经营现金流下降，可能是什么原因？”随后追问“结合我选的这家公司解释”。

**用户目标：** 快速获得解释、知道事实与推测的区别，不为普通问题承受复杂研究开销。

**旅程与成果：**

1. 普通问题直接进入主 Agent；已有信息足够就回答，不制造计划卡或虚假子任务。
2. 对选中对象作事实判断时读取明确附加且获准的资料，不能把一般解释包装成已核实的公司事实。
3. 用户连续追问时保留当前语境；需要新资料或授权时明确说明。
4. 回答可局部选择复制，上滚阅读不被流式输出拉回底部。

**异常旅程：** 资料不足明确说明；目标或授权关键项不明才提出必要问题，不把模型缺知识变成无依据断言。

### 3.1 第二意见、反证与用户纠错

**用户委托：** “这份结论哪里可能不成立？”或“这个数可能读反了，请核对并修订。”

1. 绑定被质疑的成果版本、具体断言与允许使用的证据；区分要求反证、指出疑似错误和要求改写表达。
2. 核对支持与相反证据，说明成立条件、缺口及什么信息会改变判断。没有找到反证不等于证明无风险，也不能为了“第二意见”强造反面结论。
3. 用户纠正先作为待核实线索，不覆盖可信资料；确认有误后说明数值/解释/相关成果的影响范围，无证据或证据冲突则保留争议。
4. 已结束研究的复核是关联原成果的新意图，遵 RR05；修改活动任务已派发输入时遵 F23。新答复/成果保留原版与修订关联，不编辑旧助手/工具原文，不暗改其他分支、业务记录或外部导出。

**CQ04：** 质疑必须核证据后修订，原成果保留；原始输入和精确数值见[详细设计 §10.4](./AGENT_DETAILED_DESIGN_v1.4_2026-11-03.md#104-六组可直接建立的合成成果夹具)。

复用 F01/F20/F25/F26/F29，关联 AC09、AC15、AC16、AC32、AC40；不固定增加审查 Agent 或自评循环。

## 4. S02：从业务页面或合法模块直接得到分析

**用户示例：** 选中股票点击“分析”，希望结果回当前页面，不手工复制数据到聊天。

**正常旅程：**

1. 业务调用方准备所选对象、资料范围、时点及请求身份，调用与聊天同一应用服务。
2. 模型、模式、配置和资料在受理时绑定；无需打开聊天才能执行或出现必要决定。
3. 单股可直接完成，不固定启动多专家；结果经业务合约校验回原页面。
4. 用户可打开关联公开执行记录，看到来源模块、主/子过程、模型及费用。

**异常旅程：** 等待超时/退订只结束观察，不自动取消工作；重传按同一请求查回。无 UI 时需要决定则等待，不自动批准。失败明确返回，不静默切旧链或双发。

## 5. S03：先讨论或制定计划，再由用户决定执行

**用户示例：** “先告诉我怎样研究盈利质量，不要开始查询或分析。”

**旅程与成果：**

1. 识别讨论、计划和执行模式，并明确本次范围。
2. 生成可理解的研究方法、所需资料、步骤/依赖和预期成果；用户可以调整。
3. 用户明确启动已审阅版本后才执行该计划；新的目标或资料形成可追溯修订。
4. 普通问答不强制走计划审阅。

**异常旅程：** 计划不因消息“看起来像批准”或页面切换自动开始。讨论/仅计划只理解已明确附加的资料、回答或生成计划，不派发研究查询或MCP工具，即使其只读且已有授权。需要新增取数时说明缺口和范围，由用户明确提交执行请求或按F23/RR03修订，不暗切模式或启动旧计划。模型/摘要外发仍核其实际用途和范围；必要澄清、原任务控制及用户显式管理操作按[F21模式矩阵](./AGENT_REQUIREMENTS_v1.4_2026-11-01.md#f21讨论计划与执行模式)分别处理，不能借“只读”或“管理”绕过工具权限。

## 6. S04：委托一项复杂研究，得到可核验成果

**代表委托：** “基于选中的三家公司、已有业务数据和这些公告，截至指定日期比较盈利质量和主要风险，给出有出处的表格和简报。”

**用户成功标准：** 不逐步指挥系统，不必知道内部角色；拿到回答研究问题、依据可查、缺口明确且能复制/导出的成果。

### 6.1 完整主旅程

1. 确认对象、时点、范围和成果要求；只询问会影响结果或许可的关键歧义。
2. 判断已有资料是否足够，直接研究、用工具或有价值地分工，不预设固定角色数。
3. 对确有分工的工作明确叶子输入、依赖和产出；用户看到主任务与一层子任务。
4. 独立分支并行；需要决定或暂停时，只阻塞真正受影响的部分。
5. 收到成果后核对有效版本、证据、日期、单位和缺失；全部必需工作及最终汇总成功才宣布完整成功。
6. 返回比较表、简报、证据入口及不确定性；需要导出时由用户选路径并确认覆盖。

### 6.2 必测扰动

| 发生什么 | 用户应看到什么 | 不能发生什么 |
|---|---|---|
| 资料缺失或相互矛盾 | 已读/未读范围、冲突与影响，必要时询问 | 编造数据、用正常分数伪装缺失 |
| A 等审批，B 成功，D 仅依赖 B，C 依赖 A/B | D 可继续，C 等待，A 可定位决定 | 父运行等待导致全部停止；将 B 完成冒充 D 已可推进 |

| 现有策略合法允许不可计价/仅记录用量 | 区分免费、已计价、不可计价；金额未知，实际用量仍记录，准入沿用原策略 | 把未知金额填零，或由 Agent 额外规定所有不可计价连接一律停派发 |

1. 导出绑定成果版本、格式、用户选定路径及覆盖确认；先完成受控临时输出与完整性检查，再安全发布目标，不先截断旧文件。临时文件与目标同卷；平台/文件系统不能满足安全发布时拒绝覆盖并解释，允许用户改选安全的新路径。

5. 已保存成果仍可预览/复制，研究原执行终态和费用不因导出失败改写。用户“重试导出”仅重新交付同一已保存版本、重核路径和覆盖条件，不发起模型、外部工具、查询或新研究；成果不可得须明示，不能暗中重算或替换最新版本。

**验收反例：** 在准备、写临时输出、发布前及发布后丢回执分别注入故障。旧文件在发布前失败时字节不变；新路径无半文件；发布后可核对实际文件，核不清则保留需核实；只重导出时模型/外部工具调用数不增加。关联 AC16、AC18、AC37；不增加通用文件写权限或独立任务中心。

### 9.1 排队修订、另发与派发竞态

| 用户动作与前置状态 | 身份与队列处理 | 反馈及禁止行为 |
|---|---|---|
| 编辑尚未开始派发的排队请求 B | 明确“修订此排队请求”；保留原业务意图和队列位置，形成不可变新修订，仅当前有效修订可派发，旧修订留痕 | 不同时保留两个有效待执行 B；不通过同提交键换正文绕过 RR05 |

修订与开始派发须原子仲裁：修订先成功则只派发新修订；开始派发先成功则拒绝旧版本编辑，不能两边都确认成功。撤回同理；使用旧修订提交的迟到编辑/撤回须冲突，不作用于后来版本。

修订有独立命令身份，绑定原请求、预期修订与替换后的完整输入/模式/模型/配置/资料快照。同一命令重传查回同一修订；同命令异内容冲突。初始提交键及当时输入不改，按 RR05 重传旧提交只查回原受理及当前修订状态，不能复活旧版本。成功修订后仍须派发新鲜核权，不产生额外模型/工具调用；此处不另造任务调度器。

**验收：** A 运行、B 排队，编辑 B 后队列仍只有一个 B 和原位置；显式另发才有 B/B′。覆盖编辑/撤回与派发两种先后顺序、过期修订及回执丢失，核对实际派发内容/次数和历史，关联 AC09、AC31、AC32、AC34。

|---|---|---|---|
| 加入关注并写备注 | 可复制的对象标识、研究摘要、来源/日期与限制 | 用户通过原关注列表/详情入口显式加入或修改，参见 [FR-UX-004](../USER_REQUIREMENTS.md#fr-ux-004关注列表) | 仅因生成候选或点击复制就说“已关注/已保存备注” |

### 10.3 引用后的删除与剩余副本

**首版策略：保护活动引用，不暗中为保留可读性复制源资料。** 引用关系区分源归属记录/附件/成果及其派生副本，与其他会话自有消息/成果；继承/分支中的受管原文引用不能变成未登记的永久副本。

1. 删除预览列出将清理的源主子记录、受管附件/成果、索引/摘要，以及被其他会话、排队请求、已生成计划或成果引用的影响；无法核对引用范围则拒绝删除，不假称清理完成。
2. 源被未结束的执行（含排队、等待、中断、需核实）或正在导出引用时阻止删除，指出受影响对象。用户须先明确结束/终止相关执行，或按相应修订流程解除引用并获确认；不因删除按钮自动终止或改写 B。
3. 仅剩已结束研究/未启动计划的引用时，可在用户确认影响后清理源及其受管派生副本；其他会话的引用保留最小“来源已删除”关联标记，不保留可恢复源正文的隐式拷贝，也不静默删除整个关联会话。未启动计划或后续研究用到该来源须重新选择确认，不用最新资料替代。
4. 其他会话自有消息/成果中已写入的摘录或结论、独立选择的资料，以及用户外部导出不因删除源会话自动消失。预览须明确哪些内容仍保留及分别如何清理；用户要清除这些内容须另行明确操作，不能提示“相关内容已全部抹除”。
5. 删除范围确认与新引用建立/开始使用须有一致的保护边界；预览后出现新引用应重新预检/确认。已进入删除的源不再接收新引用，不能先通过检查再被活动任务使用。部分清理失败明确待完成范围，不允许从残留索引/摘要继续把已删除来源读成完整可用证据。

**验收：** B 活动或导出中引用 A 时删 A 被拒绝；B 结束后确认删 A，B 原成果仍可查但来源显示已删除，继续使用须重选；预览说明 B 自有摘录和外部导出仍在。另测删除/新增引用的两种先后顺序和部分清理失败，不重跑任务、不跨范围清空 B。关联 AC13、AC18、AC32、AC36、AC40。

**组合验收：来源删除后重导出。** B 的独立保存成果 R1 引用 A，第一次导出明确失败并结束，已解除导出活动保护；用户按本节确认清理 A 后，仍可显式重导出保留的 B/R1，不要求恢复 A 正文。预览及适用格式保留 R1 的数值、研究时点、生成时依据限制，并分别显示当前“来源已删除/不可核验”状态；不换最新成果、不重算、不新增模型或外部工具调用。删除预览须说明此后仍可交付保留成果，但无法核验原来源。仅在 R1 本身也被清理/不可得时明确失败；原导出结果未知时先按原身份查回，不能套用明确失败路径盲重发。此为既有规则的组合验收，不新增导出权限或格式，关联 AC13、AC16、AC18、AC32、AC40。

## 17. 详细设计输入的上下文与技能契约

本节细化 F01/F13/F25/F28/F29、RR02/RR03 的既有行为，不新增功能编号、会话导航层级、调度器、恢复内核或权限。十项产品确认仍以 §16.4 为准；以下补充是本轮文档修订，不追认旧原型已支持或用户此前已逐条确认这些细节。

### 17.1 普通请求的因果上下文与修订路径

“路径”指本主会话内一条可追溯的消息/修订及因果后继选择，不是子会话或新执行栈。适用于主会话普通发送、排队及历史重发；业务 API/直接推理使用其明确提供的上下文，不借用 UI 当前会话，也不为此强制创建聊天。

1. 每次可靠受理同时绑定主会话、当前路径/修订截点、按持久受理顺序可见的前序意图及其成果接入规则，并与原队列位置、输入修订关联。界面展示可理解的“沿哪次修订继续/等待哪项前序成果”，不要求用户管理内部身份。所示路径已因另一提交发生变化时，保留草稿并要求核对，不默绑另一条路径。
2. 绑定的是合法来源选择，不是提交时整段历史文本。B 入队时 A 的回答尚未生成，A 随后可靠保存的、位于 B 已绑定因果前缀内的公开成果可在 B 派发时接入；B 之后受理的 C 不进入 B 的上下文。A 的在途模型调用也不得把排队 B/C 当作补充当前输入；显式 F23 补充另走既有协议。
3. 已受理请求不因当前页面、默认路径或普通设置变化而改绑。首次派发时保存实际采用的前序消息/成果身份及版本、缺口和输入修订，重启查回、同身份重传、继续及相同输入的明确重试均可核对，不重新按“最近消息”猜来源。成熟摘要/窗口裁剪可变化，但不能越过已绑定来源；合法补充或修订另存可追溯版本，重启不自动派发。
4. 前序失败、撤回、成果未可靠保存或被清理时，保留真实失败/缺失状态。请求明确依赖“上个结果/其中对象”却无法解析时，说明缺口，经既有澄清、修订或撤回流程处理，不借其他会话、兄弟成果或最新资料替代，也不自动重执行前序。与缺失成果无依赖的独立问题可使用其合法可用上下文，不强制等待不存在的成果。
5. 确认历史重发被可靠受理后，同会话默认路径立即指向该修订及其新后继，即使其执行尚在排队；后续普通追问沿新路径等待相应前序成果。此前已受理的队列项保持旧路径绑定，不因默认路径变化而迁移。未受理、取消编辑或提交未知不凭 UI 回执猜路径；先查回原提交。重发被撤回/失败也不默切回旧路径，后续依赖按上一条暴露缺口。
6. 切页、浏览/搜索旧记录不改变默认路径，重启查回同一默认路径且不续跑。旧后继只按显式选择作为旧证据附加，不成为修订后的因果后继；需要沿旧路径独立继续时使用既有“从历史节点另开分支”，不增加隐式切路或第三层导航。

| 反例验收 | 必须可核对的结果 |
|---|---|
| A 运行，B“根据上个比较结果”排队，C 随后改对象/截止日 | A 不读 B/C；B 取得 A 可靠保存的正确成果，不含 C；派发前重启或同键重传不改归属 |
| 同会话 `U1→A1→U2→A2` 后确认重发 `U1′`，再普通追问 | 追问沿 `U1′` 及其新后继；旧 `A1/U2/A2` 不默入。重发仍排队、查看旧历史及重启均不改变此规则，旧队列项不串路径 |
| 前序撤回/失败/成果不可得或上下文修订竞争 | 显示关联缺口/冲突并保留草稿；不猜替代来源、不重复执行。明确修订后仅使用该新修订绑定，旧记录可追溯 |

### 17.2 角色默认与单次手选的 Skill 有效集合

默认集来自本请求绑定的角色分配/启用版本；手选候选必须已安装、对主角色启用、兼容且获准。主角色按“默认集与本次手选集的并集”绑定，子角色仅绑定自身默认集，不自动继承主角色手选。按稳定 Skill 身份及绑定版本去重；同身份版本冲突明确要求重选，不能默取最新版本或同时带两版。手选不修改持久默认分配，不启用不可用技能、不授予工具权限。

“对角色启用”持久映射为该角色的enabled_skills，“默认带入”为default_skills且必须是前者的精确版本子集；Skill全局enabled及compatible_roles分别表示全局可用和兼容性，不能替代角色选择。可用但非默认的C允许主会话手选，空角色启用集不表示全部可选。字段、保存/取消及冻结合同唯一见[详细设计 §9.9/§9.11](./AGENT_DETAILED_DESIGN_v1.4_2026-11-03.md#99-默认资产解析编辑取消与教程)。

| 配置/动作（所列技能均满足相应角色条件） | 本次主角色有效集 | 本次子角色有效集 | 对后续的影响 |
|---|---|---|---|
| 主默认 A、子默认 B，无手选 | A | B | 不改角色配置 |
| 主启用A/C、默认A；子启用/默认B，主手选C；C全局启用且兼容主/子 | A、C | B | C不自动成为主默认；兼容子角色不等于对子启用，子默认不得加入未启用C |
| 同上，主会话手选 C | A、C | B | C 仅补充本请求主角色，不跨角色传播 |
| 手选 A 与 C | A、C，A 不重复 | B | 同身份冲突版本不能受理为隐式二选一 |
| 发送前取消手选 C | A | B | 只移除草稿的本次选择，不停用或卸载 C |
| 受理后更改角色分配或下一草稿选择 | 已受理请求仍为绑定的 A、C | 仍为绑定的 B | 普通配置只影响新请求；安全撤权/不可用状态仍在实际派发核验 |

单次选择绑定本请求的各主模型回合及其中断/继续；相同输入的明确任务重试保留原 Skill 快照并重新核权，不因输入框已清空而丢失。确认受理后，下一份独立草稿不自动沿用 C；普通后续发送、历史重发及新分支须重新明确手选。提交失败/未知时保留草稿选择并查回，不换身份重复发送。仅计划的手选不成为下一草稿默认；后续明确启动须展示并核对所审计划中的 C 及其版本，不自动清空或静默改变。用户保持该选择则绑定所审快照；改变手选须先修订计划并重新审阅，不能在启动时另造未受审输入。

发送前及历史详情分别显示角色、默认/手选来源、Skill 身份和实际绑定版本；“已绑定可用”不冒充模型实际调用过。普通配置停用不改变活动执行已绑定的 Skill 版本及其中断/继续；实际派发发现安全撤权或绑定版本不可得时明确阻断/要求处理，不静默丢掉 C、换版本或传给子角色绕过。普通停用与安全撤权必须分别记录；新意图不得借旧绑定绕过停用。

**验收：** 固定 A/B/C，分别重读主/子角色的启用集和默认集，再核输入快照；主C可用但非默认、子C未启用时保存/取消/重开保持区别，默认超出启用集拒绝。覆盖去重、受理未知、单次结束、仅计划后启动、排队后改分配、暂停/继续和明确重试。普通配置变化不改旧绑定，撤权不能凭旧快照绕过。关联 AC10、AC12、AC20、AC26、AC30、AC32、AC41。
