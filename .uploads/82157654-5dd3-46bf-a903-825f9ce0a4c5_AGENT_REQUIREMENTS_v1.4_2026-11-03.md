> v1.4 / 当前工程方向 E6。本文统一定义F01—F36、BR01—BR19、RR01—RR05与D01—D10；场景稿不再重复定义。产品行为和初始目标已确认，技术取证、正式权限及发行仍须独立通过。
>
> 从[阅读入口](./README.md)领取任务；完整AC01—AC41、接口/数据/状态和26张实施卡见[详细设计](./AGENT_DETAILED_DESIGN_v1.4_2026-11-03.md)。本文不覆盖[用户需求](../USER_REQUIREMENTS.md)、[项目宪法](../../CLAUDE.md)或现行ADR。

## 1. 文档用途与状态解释

F、BR、RR、D、AC分别表示功能、行为规范、修订规则、默认范围和验收场景；BR不是项目红线编号。功能分批交付不得删范围，文档/原型/原生运行/产品验收不能互相冒充。

## 2. 产品目标、对象与使用入口

### 2.1 产品目标

在当前 QTrading UI 内自然融入可扩展智能体，帮助用户完成对话研究、资料分析和复杂任务。用户能够知道正在做什么、查看子任务过程、参与必要决策、控制执行，并回顾和检索全部历史。

用户不应为了使用智能体而学习另一套后台任务管理界面，也不应被迫自行编写提示词或反复复制业务资料。

### 2.2 基本对象

| 对象 | 定义 |
|---|---|
| 主 Agent | 接收用户意图、按需处理或规划委派、汇总结果的智能体。 |
| 主会话 | 用户自由对话、提交任务、追加要求及操作任务的会话。 |
| 总任务 | 一次需要执行与跟踪的工作；不是整段会话，也不意味着必须拆分。 |
| 子任务 | 主 Agent 按需拆出的叶子任务，由 subagent 执行。 |
| subagent | 只执行指定子任务，不再拆分、委派或启动其他智能体。 |
| 子会话 | 对应子任务执行过程的只读观察窗口。 |
| 执行轮次 | 一次具体执行；重试保留旧轮次，新结果不覆盖原记录。 |
| 决策请求 | 执行所需的授权、澄清或方案选择，绑定来源任务、执行轮次与具体范围。 |
| 任务树 | 主任务与一层子任务的隶属关系。 |
| DAG | 同层子任务的执行依赖；不同于任务树。 |
| 模型工作上下文 | 本次发送给模型的有界消息、摘要和资料，不等于完整历史。 |

### 2.3 三类使用入口

1. 用户直接与主 Agent 对话。
2. 用户在股票分析等业务页面触发智能体能力。
3. 程序内其他合法模块通过 API 调用同一智能体服务。

### 2.4 两条执行路径

| 场景 | 基线要求 |
|---|---|
| 新闻分类、情绪分析等高频固定任务 | 保留场景选模型直接推理，经现有模型执行底座，不强制启动 Agent、子任务或聊天会话。 |
| 对话、综合研究、需要工具或任务协作的工作 | 使用 选定原生运行时；仍可直接回答、单 Agent 调用工具，或按需委派。 |
| 已确认的股票分析 | 经 F33 Agent API 接入 选定原生运行时，再使用现有模型网关；不固定为每股启动多个 subagent。 |
| 其他场景，如新闻风险解读、连接诊断 | 详细设计时逐项登记归属，不因名称或“统一 UI”擅自迁移；未决定前不改变原行为。 |

两条路径共享模型连接、凭据、外发授权、预算、计费、审计和底层可靠性机制。直接推理不等于任意业务模块自行使用 SDK 绕过治理。专用 FinBERT GGUF 编码分类模型不应被包装成需要对话与工具能力的 LLM。

## 3. 不可遗漏的产品与集成约束

架构与权限遵项目宪法及现行ADR；运行时选择与原生门禁仅以[详细设计 §1—§4](./AGENT_DETAILED_DESIGN_v1.4_2026-11-03.md#1-完整harness优先的选型决定)为准，不自研执行内核、不暗删需求。

**许可硬门槛：** 框架及必需运行时、模块使用Apache-2.0、MIT或标准BSD许可；其他BSD变体逐项核验。完整发行物覆盖固定制品、必需服务、插件、传递依赖/SBOM、原生二进制、LICENSE及适用NOTICE；许可未知不得准入。模型权重/素材另核，软件许可不等于模型服务免费。

## 4. 按用户操作组织的功能列表

### 4.1 首次使用：选择模型并了解提示词

#### F16：Agent 角色与系统模型选择

- 主会话提供模型选择器，只引用系统已配置的连接，显示名称、来源、能力、授权与可用状态；不可用时说明原因并提供系统设置入口。
- 请求可选择具体连接或场景默认；解析与备用边界见 RR01，不能显示 A 却静默执行 B。
- 主／子 Agent 的角色、模型及能力配置复用系统设置；子会话不提供修改入口。
- 入队后的配置不随选择器后来变化；变更须明确修订。派发仍重新检查权限、凭据、窗口和工具能力。
- 保留每次实际模型及配置来源，不能用当前选择覆盖历史。
- 新闻等直接推理场景继续有独立可见的模型选择，共享连接与治理，不与 Agent 模型选择混淆。

配置页可明确选择主角色或具体子角色，查看及编辑该角色的默认模型策略；子角色区分“继承父请求策略”与“显式覆盖”，连接仍来自唯一系统连接库。角色配置有独立草稿、保存/取消及当前有效版本，不能仅用“继承默认”的静态说明代替配置入口。普通保存只影响后续新请求，既有排队/活动执行和历史仍引用原版本；安全撤权不受旧快照豁免。

#### F35：全部提示词默认版本与配置教程

- 主 Agent、subagent 角色、股票分析、策略、新闻、摘要等提示词均有产品维护的默认版本，不要求用户从空白编写。
- 可编辑项区分默认、自定义、实际合成来源和版本；支持查看默认、基于默认修改、预览、保存／取消、确认恢复默认。
- 升级与迁移保留用户自定义；旧值来源无法证明时保留为存量覆盖或来源未知，不能凭文本相等推测未自定义并覆盖。
- 配置界面可直接打开教程，包含职责与作用范围、模型／Skills／MCP 关系、零修改使用、步骤、示例与反例、可用变量、数据来源、输出要求、保存生效及恢复排错。
- 固定安全规则、禁止递归及程序输出契约由系统维护，不通过用户 Prompt 开放权限。
- Agent 角色 Prompt 与直接模型场景 Prompt 分开维护；统一设置不意味着共用一段指令。

实际合成预览须绑定所选角色和调用场景：股票策略规则及最终股票输出合约只在相应业务调用中出现，不作为普通聊天的固定合成链。新闻、摘要与研究角色保持各自默认资产和来源，不增加第二套业务 Prompt 编辑源。

### 4.2 按需配置 Skills 与 MCP

#### F12：Skills 安装与卸载

- 用户主动导入、安装和卸载标准 `SKILL.md` 技能包；支持来源的建议范围见 D02。
- 安装前展示来源、内容、许可及版本；格式、路径安全、同名冲突和依赖缺失必须明确反馈。
- 安装或更新失败保留旧有效版本，不遗留半安装状态，不破坏活动任务。
- 安装不自动执行脚本、安装依赖或授予工具权限，不自行开发另一套技能执行框架。

#### F13：Skills 查看、启停、更新与分配

- 查看名称、说明、来源、许可、版本或内容标识。
- 区分全局已安装、当前 Agent 已启用、主／子 Agent 分配状态。
- 提供启用、停用与更新操作；记录本次执行使用的实际版本。
- 停用阻止后续新任务使用；活动执行绑定既定版本，物理卸载应先结束相关执行或延后清理。

用户可在主/子角色间切换，查看和修改 Skill 分配，取消恢复原分配，保存后再次进入能查回实际选择。取消勾选必须移除该角色的后续使用分配，不能只把一个全局“启用”标志设为真。安装、角色分配、角色启用和单次手选分别表达；未安装或不可用时说明原因，不暗中安装或启用。

#### F14：MCP 服务与凭据配置

- 新增、编辑、删除 MCP 服务及连接、鉴权配置，协议建议范围见 D03。
- 连接配置、服务启动、保存、测试、鉴权及工具授权分别表达，不能保存后就显示可用。
- 复用既有安全凭据存储或环境引用，不把秘密写入明文历史、摘要或日志。
- 本地服务启动配置不等于授予 Agent 任意 Shell 执行能力。

配置按两级选择：**接入方式＝本地进程 / 远程服务**；本地固定使用 `stdio`，远程提供 **Streamable HTTP（推荐） / HTTP + SSE（旧版兼容）**。HTTP/HTTPS 是端点 URL 方案，不与 MCP 传输协议混列；Streamable HTTP 可以返回 SSE 流，但不因此等于旧版 HTTP + SSE。

本地字段为服务名称、可执行程序、逐项启动参数、环境变量/凭据安全引用和超时；远程字段为服务名称、所选协议对应的端点 URL、无鉴权/Token/Header 安全引用和超时，不显示本地启动字段或“启动进程”按钮。旧版 SSE 的消息端点由服务器协议发现，不要求用户手填第二个端点。目录同时显示服务来源、接入方式及协议，切换方式、协议或服务保留未保存草稿；保存不自动连接，配置变化须重新测试。

删除入口须绑定具体服务身份及配置版本，先预览角色默认引用、排队/活动执行、已启动本地进程或连接、在途测试/工具调用及历史影响，再允许取消或确认；影响范围查不清时拒绝删除，不假称无引用。删除不能隐式终止任务、改写已受理快照或自动杀进程。活动引用按 [场景需求 §16](./AGENT_REQUIREMENTS_SCENARIO_v1.4_2026-11-03.md#16-dr1-设计输入状态与产品确认) 已确认的 DI-02 阻删，明确解除引用或停止/断开后重新预检；产品确认不替代真实操作的逐次确认及工程准入。历史仍保留最小来源和版本关联，不因配置删除伪装成从未使用。

删除鉴权定义指移除本服务保存的凭据引用映射，不读取或删除共享安全存储条目、环境变量或其他服务配置；旧业务授权不得借同名重建服务自动复用。本地进程/连接需要停止时应提供明确独立操作及结果核对，远程断开不等于关闭远端服务器。

#### F15：MCP 连接测试与工具调用

- 测试连接，列出并选择工具；名称冲突应能区分服务来源。
- 只向 Agent 暴露获准工具，真实派发处再次检查权限。
- 工具身份、参数、结果及错误可追溯；参数或身份变化重新校验批准范围。
- 超时、断线、重连、鉴权失效和工具变更有界处理，错误或未知结果不能伪装空成功。
- 非幂等调用不因断线自动重发；工具中间响应不能被误当作最终业务结果。

保存、仅本地的进程启动、连接、鉴权和业务工具授权是独立状态。连接可达但鉴权失败不能显示为可调用，失败不得沿用旧工具目录；测试成功也不授予业务数据调用或外发权限。原型中以上启动、测试、失败和工具发现均明确标记模拟，不实际启动进程、解析凭据引用或访问网络。

### 4.3 新建会话并表达任务

#### F01：主 Agent 多轮对话

- 用户提交大任务、提问、追问、补充要求并查看结果，普通自由对话只进入主 Agent。
- 同一主会话的总任务与后续排队请求有明确归属，不隐式覆盖旧任务。
- 按 RR02 区分执行占位、推理并发与控制命令；独立工作可另开主会话。

新建研究创建独立主会话身份和输入现场，切换只改变当前观察对象，不清空原会话的消息、未发送草稿、任务、队列、未决决定、费用或资料绑定。会话目录按身份打开对应记录，名称不是身份。新会话可以为空，但原活动会话仍可从目录/全局状态返回并按原限额推进；不得以重置一个全局状态对象冒充新建或切换。

#### F20：显式引用业务上下文与附件

- 可引用用户选中的股票、股票池、策略、回测、资讯、附件或历史会话。
- 已附资料可见、可移除，显示来源、日期、范围和读取结果；不默传整库或其他聊天。
- 附件支持范围见 D06；缺失、过期、不支持、超限或部分读取必须解释，不能静默截断。
- 排队资料引用的身份、版本与时点按 RR03 处理；历史分析不能被当前快照替代。

每项未发送资料引用有明确“从本次草稿移除”入口；移除后更新对象/资料范围摘要，并从下一次提交快照中排除该引用。移除只改变本次草稿，不删除源文件、历史证据、其他会话引用或已经受理的输入。已受理/排队输入须显式修订，活动输入按 F23 处理；不能把草稿移除按钮当作热改执行或 F30 的受管来源删除。用户自行粘贴在正文中的内容不因移除附件自动抹除，发送前仍须核对正文与实际外发范围。

#### F21：讨论、计划与执行模式

- 区分讨论、只生成计划、执行任务；讨论中的“只读”指理解用户已附资料或查看已存记录，不表示可调用只读研究工具。
- 用户明确要求先规划或选择计划模式时，不直接执行任务。
- 执行模式下可直接完成或按需委派，不为普通回答强制计划卡或审批步骤。
- 确需多步骤执行计划时提供可审阅、调整和启动的流程；模式不扩大权限。

**模式 × 能力矩阵（UI/API同一边界）：**

| 能力 | 讨论 | 仅计划 | 执行 |
|---|---|---|---|
| 对已明确附加且可用的资料进行模型理解、必要摘要 | 受治理回答问题 | 受治理生成/修订计划，不开始研究 | 受治理按目标处理 |
| 用户查看已存资料/历史、查找、复制和教程 | 允许，纯浏览零模型/研究工具调用 | 同左 | 同左 |
| Agent请求业务取数、外部检索或MCP研究工具，即使工具只读且已有授权 | 不派发 | 不派发 | 仅在正式准入、准确授权及派发检查通过后按需调用 |
| 启动研究步骤或委派叶子任务 | 不启动 | 不启动，交付计划不等于启动 | 按需单层执行，不强制拆分 |
| 必要澄清、方案选择及既有任务控制 | 可达，仅交准确原请求 | 同左 | 同左；回答不自动批准外发 |
| 用户显式管理操作，如资料登记、配置/连接测试、导出与清理 | 独立于研究模式，分别核其权限与确认 | 同左 | 同左；不因此给模型管理权限 |

研究工具由“Agent请求并派发新的业务取数、检索或MCP调用”界定，不按工具名称、只读声明或是否修改数据判定。应用按用户明确选择的对象/版本准备已有资料、读取受管资料及必要澄清控制协议不属于研究查询工具，但不得借此自动扩对象、换新版本或访问未选资料；模型外发和摘要仍按实际范围核权。连接测试等用户管理命令也不等于Agent研究调用，讨论模式不能阻止用户控制原有活动任务。

讨论/仅计划发现需要研究工具时，说明缺口与转执行的范围，保留输入；用户须明确提交执行请求，或按 F23/RR03 修订原请求。不得由模型、已有批准或普通模式选择器暗改已受理输入，也不得仅改工具名称绕过模式检查。切换模式本身不启动旧计划或放宽工具/外发许可。

**仅计划的生命周期：**

- 生成计划本身是一次受治理请求：生成期间遵守会话仲裁，实际模型、摘要及费用如实计入，研究工具派发数为0；必要澄清不启动研究，失败或保存未知不伪装完成。
- 计划已可靠保存并交付后，这次“仅计划请求”完成，释放会话执行占位和推理资源。计划卡标明“执行未启动”，不是永久占位的“等待启动任务”；用户可继续讨论或提交其他工作。
- 修订保留旧计划并生成新版本，不启动研究。用户明确启动时创建新的执行意图，引用明确审阅的计划版本及其配置/资料快照；启动操作本身不等于全面授权。
- 启动前展示绑定范围。普通选择器不暗改计划；原资料不可得、版本冲突或用户要改模型/资料时，先确认修订与相应审阅，不静默换最新值。
- 同一次启动的双击/重传查回同一执行；明确再次执行是新意图。原会话已有活动任务则排队，不抢占；旧计划在修订后不能被迟到的旧按钮误启动。
- 执行模式中已经开始的任务若等待必要计划审阅，仍按 RR02 保持原执行占位；这与完成一次仅计划请求不同。

#### F28：手动选择 Skill

- 主会话通过 `/` 或选择器检索、选择已启用技能，显示用途与本次作用范围。
- 未安装、停用、不兼容时提示，不暗中启用；子会话不提供用户命令入口。
- 不完全依赖模型自动选技能，但手动选择也不绕过工具权限。

手选追加到本次主角色的默认 Skill 集，不替换默认分配、不自动传播给子角色，也不修改角色持久分配。有效集合、去重、版本与单次结束边界按 [场景需求 §17.2](./AGENT_REQUIREMENTS_SCENARIO_v1.4_2026-11-03.md#172-角色默认与单次手选的-skill-有效集合)；发送前显示本次主/子角色实际绑定范围。

### 4.4 由 Agent 按需处理或拆分任务

#### F03：自主判断是否规划、使用工具或委派

- 主 Agent 根据目标、专业分工、依赖关系和开销选择直接回答、自己调用工具或委派。
- 不按长度、关键词、复杂程度标签或股票数量机械拆分，不把多 Agent 数量当质量指标。
- 需要拆分时明确各子任务的目标、执行角色、依赖、输入及预期产出。
- 仅形成一层叶子任务，授权与必要计划审阅不因自主选择而省略。

#### F04：同层 DAG、依赖调度与汇总

- 只有实际拆分后才形成 DAG；未拆分任务不制造虚假子任务或空图。
- 拒绝循环、自依赖、缺失引用、不可用角色或能力。
- 前置满足后派发，独立分支按限额并行，结果传递有明确来源。
- 必需前置失败或中断时后继不执行；独立分支可继续，失败收敛按 BR03／RR02。
- 前置变化使受影响下游失效，全部必需子任务成功且汇总完成才是整项成功。

#### F05：Subagent 独立执行

- subagent 使用独立上下文及授权模型、Skills、MCP，向主 Agent 返回必要结果和证据引用。
- 不复制全部主／兄弟会话；任务资料与执行结果必须隔离并关联正确来源。
- 只接受主 Agent／统一调度提供的输入，不直接收用户自由指令。
- 不再拆分、委派或启动其他 Agent，包括借助工具间接递归。

### 4.5 用户观察执行过程

#### F02：流式公开消息与执行展示

- 流式显示公开回复、工具摘要、调用与执行状态，不展示模型隐藏推理。
- 详情渐进展开，不用日志淹没主对话；部分失败、等待和未保存状态真实可见。
- 上滚阅读不被强制拉回底部，提供新消息提示与返回最新位置入口。
- 事件丢失、重复、乱序和重连不应重复消息或回退已确认终态；不能为补观察记录而重执行工具。

#### F06：主会话内任务树

- 展示主任务、一层子任务、负责人、状态和成果入口，支持查看依赖。
- 树表达隶属关系，DAG 表达执行依赖，二者不混淆。
- 不要求用户前往现有任务中心，也不设计递归层级。

#### F07：真实进度与任务详情

- 显示计划、排队、运行、等待依赖／用户、中断中、已中断、需核实、成功、失败、终止及阻塞原因。
- 状态来自框架实际记录与事件；无可靠分母时用阶段和完成数，不伪造百分比。
- 区分控制请求与实际生效、子项与总项；观察重连以权威持久状态核对补齐。

#### F27：模型、能力、用量与费用透明

- 展示当前选择和每次实际模型、候选来源、生效 Skills／MCP。
- 区分本轮与累计；主 Agent、subagent、摘要和所有实际尝试统一计量。
- 重试不清零已发生费用，未知费用不当免费，免费与不可计价明确区分。
- 复用现有网关的授权、计量、审计与预算，不重复记账或隐瞒框架重试。

确定到限、治理读取失败和合法 `usage_only` 分开处理。仅计用量不意味着免费或零元；是否允许派发由现有治理策略裁决，Agent 不新增计价准入规则，也不以 `usage_only` 掩盖授权或账本错误。

#### F31：状态与待处理提醒

- 任务完成、失败或等待输入时给出站内／会话提醒，可定位关联任务与主会话。
- 普通提醒不抢焦点或滚动；必要决策按 F36 使用系统提示框。
- 切页后仍可找到待处理入口；不默认增加邮件、短信等外部通知服务。

### 4.6 打开只读子会话并返回

#### F08：查看 Subagent 会话

- 从任务卡或任务树进入对应子会话，标注任务、实际模型、执行轮次及只读状态。
- 查看公开消息、工具、进度、错误和成果，可查找并选择复制。
- 不提供自由输入、追加指导、修改模型、编辑重发、分支执行或直接控制入口。
- 系统必要决策仍可通过 F36 弹框处理，不因此开放自由聊天。

#### F09：返回主会话并保留现场

- 只设计主／子两级导航，子会话有明确的返回主会话入口。
- 保留各自阅读位置及主会话草稿和任务选择；子会话没有用户输入草稿。
- 切换、关闭子视图、查看历史、查找和复制均不改变任务执行状态。

### 4.7 授权、澄清与选择方案

#### F22：响应必要澄清

- 缺参数、目标不清或需要选择方案时，提供明确问题、选项和关联任务。
- 通过 F36 系统提示框收集必要输入，不仅写在聊天正文。
- 受影响任务等待用户，无关分支继续；响应经统一主调度交回任务，不盲猜。

#### F24：工具及数据外发审批

- 提示来源 Agent／子任务、工具、脱敏参数、目标、数据外发范围及副作用。
- 支持允许、拒绝、稍后、授权范围说明、查询与撤销；批准绑定具体请求与实际范围。
- 安装 Skill、连接 MCP 或选择模型不等于批准全部工具或数据外发。
- 原范围内有效授权可复用；新增私人附件、聊天摘要、MCP 资料不能被旧公开行情授权隐式覆盖。
- 关闭、超时、过期、参数变化和撤权不默认通过；真实派发前重新核验。

#### F36：统一应用级决策提示框

- 主 Agent 或任一 subagent 需要授权、方案选择或必要决定时，必须使用统一系统提示框，而非仅聊天、日志或短暂 Toast。
- 用户在主会话、子会话或其他业务页均可决策，不要求先回主会话。
- 显示来源会话、子任务、轮次、请求原因、选项、建议和影响；秘密信息脱敏。
- 多请求排队，不叠框、不重复批准；稍后与再提醒按 RR04。
- 决策响应绑定原请求并经统一主调度提交，子会话仍然只读。
- 已终止、撤销、过期或参数变化后的旧弹框不能误批准；关闭、Esc、超时不是同意。
- 与现有设置 Dialog 安全交接，保留原表单及焦点，旧 Enter／输入法事件不得穿透为新批准。
- 决定、来源与结果留存历史；无可用 UI 时 API 返回等待，不自动批准。
- 必要决策弹框是普通“不抢焦点”原则的限定例外，不默认要求 Windows 原生弹窗或外部通知服务。

“回答已保存”“已交付运行时”“任务实际恢复”分别呈现。答复先可靠记录，使用稳定控制命令身份交接；崩溃、超时或回执丢失可按原身份查回，不能先标为已消费后永久丢失响应，也不能换身份重复恢复。结果未知保持待核实，不显示已恢复；审批与终止竞态按原生生效顺序核对，终止后旧批准不能复活任务。重启只查回，不自动补发会启动执行的命令；交接边界见[详细设计 §4.5](./AGENT_DETAILED_DESIGN_v1.4_2026-11-03.md#45-k04应用事务与原生交接的真实边界)，完整答复读模型见其§5.10。

### 4.8 控制任务或补充要求

#### F10：总任务与单子任务控制入口

- 主会话任务卡／树明确区分总任务和单子任务的中断、继续与终止。
- 显示请求提交、正在处理和实际终态，不能点击后立即假称停止。
- 子会话不直接控制执行；控制请求不作为新任务排到执行队尾。
- 中断不能实现为不可恢复终态取消；停止外部操作不是回滚。

#### F32：中断后继续

- 保留计划、依赖、会话和已成功结果，从框架有效检查点或可恢复边界继续，不默认重做整项。
- 单独中断 A 不停止无依赖 B；依赖 A 的后续任务等待。
- 中断／等待保留会话执行位置但释放推理并发，继续与后续队列仲裁按 RR02。
- 不承诺任意指令点无损暂停；在途工具未知结果须核实，不能重复不确定的副作用。
- 应用退出、崩溃及跨重启范围见 BR08、D04 和实施准入，不将历史持久性冒充执行可恢复性。

#### F11：失败或终止任务重试

- 明确创建新轮次，保留旧消息、错误、结果和费用，不覆盖原记录。
- 复用输入、数据和计划仍适用的成功前置／兄弟结果，影响下游失效或重新执行。
- 同任务不并发派发两个有效轮次，旧轮次迟到结果只归旧记录，不覆盖新成果。
- 已结束任务重试服从会话队列，不抢占当前任务；与提交重传、继续和历史编辑分别表达。
- 非幂等外部调用结果未知时先核实，不因点击重试而盲目重复。

#### F23：追加指令与消息排队

- 用户仅在主会话区分“补充当前任务”和“排队下一任务”，显示排队、送达与生效范围。
- 未开始的排队请求可撤回；资料、模型、模式和配置绑定按 RR03。
- 无须修改已派发输入的补充在安全边界生效；确需改进行中子任务时先中断，再形成新计划版本。
- 编辑已有排队请求须明确确认修订并保留痕迹，不因后来操作选择器或另开分支而暗改旧请求。

### 4.9 持续长时间对话

#### F25：长上下文、摘要与压缩

- 优先复用 选定原生运行时 原生 `原生压缩`、`原生摘要能力` 及历史读取能力，不自行开发摘要内核或叠加另一 Agent 框架。
- 将原始公开历史与每次模型工作上下文分离，摘要不删除、覆盖完整消息；主／子原文仍可查看、查找和复制。
- 按实际模型及路由候选窗口计算系统指令、工具 schema、Skills、资料、历史和输出／安全预留；摘要自身输入输出也受限，不照搬固定 token 阈值。
- 采用可信当前目标与约束、结构化任务状态、受控摘要、近期完整消息及必要引用；任务状态与权限不能由自由摘要推断。
- 保留用户纠正和最终决定、范围与禁止事项、依据、日期、单位、风险、缺失、待办、阻塞和任务／结果引用。
- 工具调用与返回保持配对，大结果优先原生卸载和有界读取；需要细节时按消息或来源引用查回原文，不反复重塞整段历史。
- 主／子分别管理上下文，主只接必要子结果及引用；不默认增加向量库或长期用户记忆系统。
- 摘要模型显式使用授权的系统模型连接，经现有预算、计费和审计，不默认直连框架供应商。
- 压缩失败、为空、仍超预算或存档失败须明确反馈，不静默丢原文或伪装成功；无法安全请求时保留可恢复现场。
- 模型切换和中断继续时重核窗口；显示压缩状态及可取得的用量，不能清除草稿、抢焦点或破坏选区。
- 摘要有损，不能承诺零信息损失；Agent 与 Team 的实际原生覆盖必须分别验证。

### 4.10 审阅并使用成果

#### F26：结构化成果预览、复制与导出

- 支持报告、表格、候选股票、回测分析等成果的预览、复制和导出。
- 显示来源、日期、单位、子任务依据与不确定性；部分缺失或失败不得包装为完整成功。
- 导出格式建议见 D07；路径由用户选择，覆盖已有文件须确认。
- 不将导出权限扩展为任意文件写入或自动交易，不声称会话分支可以撤销外部操作。

导出使用明确选定的已保存成果版本；失败、取消、结果未知及独立重试遵 [场景需求 §7.2](./AGENT_REQUIREMENTS_SCENARIO_v1.4_2026-11-03.md#72-导出失败取消与独立重试)，不以导出失败触发研究重跑。

### 4.11 回顾、查找与整理历史

#### F17：全部 Agent 历史会话查看

- 全部主／子公开消息、工具记录、计划任务关系、模型／技能引用、成果及失败／中断／终止／重试轮次持久关联，重启应用仍可查看。
- 原记录不被摘要或消息编辑覆写，不只保存主 Agent 摘要。
- 无模型、无 MCP 或摘要失败时仍可纯浏览原历史，不触发推理或摘要。
- 非 Agent 直接推理不强制生成聊天；其结果仍在业务域和统一用量／审计中可追溯。

#### F18：全量历史与当前会话查找

- 支持中文／英文关键词，覆盖标题及公开消息正文，主／子及归档内容可检索。
- 支持按智能体、主子类型、时间和状态筛选，显示所属主会话及命中摘要。
- 打开结果定位原消息，返回保留关键词与结果位置。
- 查找不依赖可用模型、不触发任务；索引滞后或失败不能伪装为没有历史。

全局历史、当前主会话及当前只读子会话分别提供可达的查找范围，默认范围在界面明示，不能用全局查找代替当前会话查找。结果携带所属主/子会话身份及具体消息定位信息；打开后核对目标记录并定位/标记命中，不能只跳到固定示例页后提示“已定位”。定位暂不可得时保留搜索现场并说明原因，不展示另一会话冒充原文。时间筛选须明确使用会话创建时间还是消息发生时间，不用研究信息截止日代替。

#### F29：选中复制、消息修订与分支

- 主／子／历史会话中的消息、工具可见文本、代码块和表格文本支持鼠标局部选中复制、Ctrl+C 与右键复制。
- 整条消息、代码块复制是补充，不能代替局部选择；流式更新不丢选区。
- 仅主会话允许编辑重发、从历史节点另开可追溯分支，保留原记录。
- 分支不是任务重试或外部回滚，不自动重复原工具操作，不迁移原队列。

**编辑、重发与分支的处理语义：**

| 操作 | 上下文、身份与执行 | 不能改变什么 |
|---|---|---|
| 编辑尚未开始派发的排队请求 | 优先适用 F23/[场景需求 §9.1](./AGENT_REQUIREMENTS_SCENARIO_v1.4_2026-11-03.md#91-排队修订另发与派发竞态)，修订原意图的单个队列项；不走历史编辑重发 | 原队列位置与初始提交事实不变，不新增第二个有效请求 |
| 编辑已开始或已结束请求的用户消息 | 保留原文与修订关联；未确认重发不执行，不改助手/系统/工具记录 | 原计划、已派发输入、旧回复与工具事实 |
| 确认历史消息编辑重发或明确另发 | 新意图/新执行，使用选定节点之前的可用上下文及修订消息；原节点之后的回复/结果不冒充修订后的历史。原会话活动任务未结束则排队 | 不自动中断/撤回原任务，不混同 F23 的排队修订/补充当前或 F11 的重试 |
| 从主会话历史节点另开分支 | 新主会话记录源会话、节点/修订与上下文截点；可预览继承范围，明确发送后才创建新执行 | 原会话的活动任务、轮次、队列、未决审批和执行检查点均不迁入 |

继承的公开文本/成果只是历史证据，不重放工具调用；不复制原批准为当前有效许可。新执行显式绑定模型、配置和所选资料，重核权限、资料适用性和时点；不可得或过期明确提示。原会话及后续旧记录仍可追溯。子会话继续只读，无编辑重发/分支执行入口。

“不迁入原任务/队列/审批”只限制新分支的继承，不意味着清除源会话。准备分支前后，源会话身份、活动执行、队列、决定、草稿和阅读现场均保持；用户可返回源节点。分支另存源主会话、节点/修订和上下文截点，不能只把当前会话改名或换截止日来冒充分支。

同会话历史重发被可靠受理时，后续普通发送的默认上下文路径转向该修订；即使重发仍在排队，也不能把旧后继混入新路径。已受理的旧队列项保持各自绑定，查看旧记录不切换路径；切页和重启保持默认路径但不自动执行。沿旧路径另行研究使用既有历史分支入口，具体接续与反例验收见 [场景需求 §17.1](./AGENT_REQUIREMENTS_SCENARIO_v1.4_2026-11-03.md#171-普通请求的因果上下文与修订路径)。

#### F30：会话重命名、置顶、归档与受控清理

- 提供主会话重命名、置顶、归档，保持主子关联；归档不删除且仍可查找。
- 删除范围与保留周期须明确；删除主会话时说明关联子记录、应用附件／成果副本及索引的清理范围并确认。
- 活动任务先结束或终止；删除不撤销外部动作，不删除业务原始数据或用户已经导出的外部文件。
- 默认保存与空间策略建议见 D09，不承诺无限空间。

其他会话、排队请求、计划、成果或导出引用了这些资料时，另按 [场景需求 §10.3](./AGENT_REQUIREMENTS_SCENARIO_v1.4_2026-11-03.md#103-引用后的删除与剩余副本) 执行影响预检和剩余副本说明，不能只检查被删会话自身是否结束。

### 4.12 从现有股票分析功能使用 Agent

#### F34：股票分析接入与提示词配置迁移

- 调用链统一为：现有股票分析入口 → F33 Agent API → 选定原生运行时 → 现有模型网关 → LLM。
- 不保留业务独立直调的并行路径，也不在 Agent 失败后静默回旧链；旧公共接口可保留薄兼容转发。
- 保留数据准备、策略语义、质量及时点限制、结构化输出与缺失状态；不顺带改数学筛选、同步或回测算法。
- 单股可直接完成，不固定启动多 subagent；结果仍回原业务页面，并可查看对应 Agent 执行记录。
- 业务请求使用自身资料，不自动混入其他用户聊天或无关会话历史。
- 迁移旧全局分析 Prompt、策略自定义／内置模板和页面补充指令，保留原值、优先级及来源，不留两套编辑来源。
- 提示词区分：不可覆盖安全／执行约束、可编辑角色系统指令、场景／策略规则、当次输入与输出 schema；股票 JSON 不约束所有聊天。
- 合法工具中间响应不是最终股票输出，不能因 `content` 为空而错误触发最终校验或备用切换；最终结果仍严格校验。
- 历史时点约束覆盖工具、子任务、摘要和中断继续后的新增资料；今日快照或未来公告不得静默进入正常历史评分。
- 原提示词来源版本不能证明时保留为存量覆盖／未知，不以文本相等推断可覆盖。
- 统一智能体设置包含提示词、模型引用、Skills、MCP 与权限预算，但模型连接和凭据仍使用系统唯一来源。
- 新闻分类、情绪等直接场景保持独立，不因 UI 统一而全部 Agent 化或套用股票 Prompt。

### 4.13 由程序内其他模块调用

#### F33：应用内智能体 API

- 提供稳定、类型化的 Python 异步应用服务接口，UI 只是消费者之一；不默认增加 HTTP 服务或端口。
- 合法上层通过服务注入调用，不依赖聊天控件、Flet、Page 或 ViewModel，不操纵 选定原生运行时 内部对象，遵守单向分层。
- 支持结构化请求与业务上下文、Agent 配置与模型选择、会话／任务／执行标识、异步等待、状态与进度事件、结构化结果、历史及授权控制。
- 模型解析同 RR01，提交身份与重传同 RR05；不按文本判断重复，不双发或双记账。
- 程序发起的主／子会话在 UI 可查看、查找，显示来源模块。
- 订阅断开或等待超时不自动取消任务；取消须明确控制命令，观察恢复不重执行。
- 需人工决定时发布同一结构化请求，UI 用 F36 提示框；无可用 UI 时保持等待，不自动批准。
- 调用方不能绕过主调度向 subagent 注入指令或突破一层约束。
- 权限拒绝、取消、预算不足、失败及未知结果结构化表达；共享既有治理，不替代新闻等直接模型服务。

### 4.14 开发前评审完整用户体验

#### F19：自然融入当前 UI 的可交互原型与 UX 验收

- 基于现有导航外壳、主题 token、字号、间距、输入、按钮、表格及通知习惯做增量融合，不另套割裂的聊天站点皮肤。
- 提交完整可点击原型、页面／状态说明、交互标注及 F01—F36 与验收的覆盖对照；不是单张截图或文字原则。
- 覆盖业务上下文进入、新会话、系统模型、模式、技能／资料、计划、单层任务／依赖、主子导航、统一控制、全局决策、历史搜索、管理、摘要、成果及教程。
- 页面状态包括初始、加载、空、未配置、运行、等待、成功、失败、停止、部分完成及恢复；错误说明下一步并保留输入和有效成果。
- 用户输入与阅读体验包括中文输入法、多行发送、重复提交防护、局部选择复制、草稿、滚动位置、焦点和新消息提示。
- 宽窄窗口、中英文、既有主题及键盘基本路径可用；关键入口不能只靠悬停、右键或颜色。
- 子会话显式只读，必要授权／方案选择由全局提示框处理；普通状态不抢焦点。
- 缺模型／MCP、授权撤销或摘要失败时，历史、查找、复制和默认教程仍可用。
- 原型以显式模拟数据演示，不连接真实模型、MCP、交易或数据库来冒充能力验证。
- 具体几栏、面板和导航布局在原型评审确定，不把方向确认视为真实布局验收。

原型须串起 [场景需求 §1.5](./AGENT_REQUIREMENTS_SCENARIO_v1.4_2026-11-03.md#15-用户目标到场景成果验收和责任) 的用户目标与新增子旅程：候选/不匹配/待核实、资讯依据与观点、被质疑/已核实修订、新旧研究时点、人工业务接续各可走通。它们复用现有会话/成果/业务入口，不增加四套导航或要求用户理解内部 Agent 结构。

## 5. 配套行为规范 BR01—BR19

本节约束多个功能的组合行为，不新增功能编号。涉及 RR 或 D 的规则须连同其状态阅读。

## 6. 对抗性检视后采用的具体规则

RR01—RR04的产品行为已确认；RR05的幂等要求保留，准确类型见详细设计。产品确认不改变现行模型配置或真实执行权限。

### RR01：显式模型与场景候选

1. UI 和 API 使用同一个结构化模型选择概念，不同时给出两个互相矛盾的选择。
2. 优先级：本次显式选择（具体连接或场景默认）→ 绑定 Agent 配置的默认选择 → 该业务入口明确绑定的场景默认。
3. 无有效选择时要求配置，不借用其他聊天的当前模型。
4. 指定 A 仅使用 A，不自动回退 B／C，也不修改全局路由。A 无权限、不适用或不可用时明确拒绝或失败，用户可另选。
5. 场景默认才使用该请求所绑定版本的原有有序候选，所有备用均遵循同一治理。
6. 子角色的显式模型覆盖优先，否则继承父请求的模型选择策略及候选版本，不默转不同子场景。
7. 派发前可解释选择来源、候选与覆盖，实际模型保留记录；此规则不意味着新增 Router。

### RR02：中断等待与会话队列仲裁

1. 每主会话一个未结束总执行占位，包含中断、等待用户和需核实；这不是模型推理并发槽。
2. 后续新执行排队，查看、审批、继续及终止等控制命令可直接处理，不被队列阻塞。
3. 等待和中断不占推理并发，其他主会话可在全局限额内运行。
4. 继续中断任务保留原占位；若要独立执行其他任务，可另开主会话或先明确结束当前执行。
5. 必需前置失败，且无独立可运行、可恢复或待决定分支时，总任务结束为失败／部分失败，后继注明未执行原因并释放占位。
6. 已结束旧任务的重试是新执行；同会话已有活动任务则排队，不抢占。

仅计划请求生成并可靠交付计划后已结束，不因计划尚未启动继续占位；以后明确启动是新执行，遵守同一队列。执行中的计划审阅等待仍占原执行位置，不能用前一规则释放活动研究。

### RR03：排队请求绑定时点

1. 发送入队时固定消息正文、模式、具体模型／场景候选版本、Agent 配置、已审阅计划版本及资料引用身份与时点。
2. 后续普通配置和选择器修改仅影响新请求，不暗改既有队列。
3. 资料内容必须符合原引用版本／时点；不可取得时请求重新选择确认，不静默取最新值。
4. 权限、凭据及真实工具准入仍派发新鲜核验，快照不是永久许可。
5. 浏览或另开历史分支不迁移原队列；显式修改排队内容形成可追溯修订。

“固定”指每个已受理修订的快照不可变；显式排队修订按 [场景需求 §9.1](./AGENT_REQUIREMENTS_SCENARIO_v1.4_2026-11-03.md#91-排队修订另发与派发竞态) 形成新修订并保留旧版，不等于允许同一提交身份更换输入。

普通排队请求还须按 [场景需求 §17.1](./AGENT_REQUIREMENTS_SCENARIO_v1.4_2026-11-03.md#171-普通请求的因果上下文与修订路径) 绑定上下文路径、可见前序意图及其成果接入规则；固定这些选择规则，不等于冻结提交瞬间尚未生成的前序回答，也不允许派发时直接取整条会话的最新历史。

### RR04：“稍后”的呈现策略

1. 稍后关闭当前决策并暂缓当前这一批已到达请求的连续自动弹出。
2. 保留醒目待处理入口，用户主动打开时逐项处理；切页和刷新不让该批次立即重复打断。
3. 稍后不批准、终止或恢复任务，不改变请求有效期。
4. 新到请求仍按串行规则呈现，但不叠框或抢走正在输入的普通 Dialog；安全交接遵 F19／F36。

### RR05：程序提交的业务身份

1. 调用方在首次提交前提供当前用户域、来源模块及业务请求标识；同一意图重传保持标识。
2. 同身份、同规范化输入返回同已受理／运行记录，不重复派发或记账。
3. 同身份、不同输入明确报冲突；同文新意图必须用新标识，不按文本去重。
4. 已持久受理跨重启可核对；受理结果无法确认或相关历史已清理时返回未知／需核实，不默认新建执行。
5. 主动重试与分支使用独立命令身份并关联原执行，不混同提交重传。
6. 复用框架与现有存储能力；不要求最终用户手工管理请求键，不在此规定 HTTP、TTL 或新调度存储实现。

排队修订使用独立修订命令关联原意图及预期版本，不改变初始提交键的幂等含义；旧提交重传不得撤销修订或重新入队旧输入，界面/API 应同时呈现原受理和当前有效修订。

| D03 | 本地 stdio；远程 Streamable HTTP（推荐）或用户显式选择 HTTP + SSE（旧版兼容）；环境/安全存储令牌或 Header；不自动切协议，不含 OAuth/MCP Apps/未适配自定义传输 |
| D04 | 单机当前用户，切页可继续，应用真正关闭即停；重启展示历史和中断/未知，有可靠检查点才由用户手动继续；无默认守护/定时/云端/外部独立 Agent |
| D05 | 每主会话 1 个未结束总执行；全局 2 个总任务、4 个叶子，每总项最多 3 叶并行，单计划最多 20 叶，取各层最严格值。总/叶活跃时限初始默认 60/15 分钟，不计等待/主动中断；总项最多 100 次模型请求含摘要、200 次工具调用；工具有限超时，模型超时/费用沿系统，任务自动重跑关闭，均须运行验证 |
| D06 | TXT/Markdown/CSV/JSON/XLSX/文本 PDF；PNG/JPEG 仅模型支持；扫描/加密 PDF 提示预处理，不默转外部 OCR。每条 5 件、单件 20 MB，有界提取、部分/超限可见 |
| D07 | Markdown/CSV/XLSX 按成果类型提供，用户选路径/覆盖确认；PDF 另评估 |

| D09 | 默认不自动删，归档可检索，空间用量/告警及主动确认清理；不新增多用户/云同步/独立备份系统 |
| D10 | 16 GB、SSD、本机 PostgreSQL 参考环境；1000 主会话、10 万公开消息、长会话 1 万条、单任务 20 叶；排除远端推理等待，本地反馈 P95 200 ms、事件到 UI 1 s、最近 50 条首屏/搜索 2 s，最小宽度 1024；记录硬件/版本/数据/冷热缓存实测，不承诺外部工具即时停止 |

## 10. 定稿边界、实施准入与暂不纳入事项

### 10.3 不因本需求自动纳入的事项

- 递归子任务、多级 Team、用户在子会话自由发消息或改模型。
- 将每条新闻或全部模型推理改为 Agent。
- IDE、代码补全、Git／worktree 操作和任意终端／脚本执行能力。
- 自动交易、资金操作、核心配置或业务数据库写入权限。
- 云端平台、远程守护运行、多设备同步、定时触发和应用关闭后持续执行。
- 外部独立 Agent 协议、技能市场、自动下载／更新、额外向量数据库或长期用户记忆系统。
- 任意时点无损暂停、外部操作绝对只发生一次、聊天分支撤销全部副作用。

这些事项若有后续明确请求，应另行评估并记录范围变更，不能通过本文件的泛化表述默认实现。
