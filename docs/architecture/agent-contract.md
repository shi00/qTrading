## 1. 用途与效力

本文件是 [ADR-0016](../adr/0016-agent-permission-exception.md) 的操作契约，承载 E1—E5、RR01—RR05 与 D01—D10 的批准值与审批回执。

- 本文件不修改 `CLAUDE.md` 红线、不修改任何运行期权限或工具门控；运行期工具、MCP、导出与持久化仍须通过 G02/G03/G04/G05 门禁。
- `authorized_for_preflight`（实施前验证授权）不等于正式批准，也不等于 G02/G03/G04 通过。

## 2. 现行约束与冲突点

| 现行正本 | 当前约束 | 与本需求的冲突点 |
|---|---|---|
| [ADR-0008](../adr/0008-no-ai-execution.md) | AI 输出仅用于评分和文本展示；禁止触发交易/资金、调用外部工具、生成或执行代码、修改核心配置或数据 | 需求基线要求 Agent 在用户授权范围内读取业务资料、调用已审核 MCP 只读工具、用户确认后导出成果 |
| [ADR-0014](../adr/0014-unified-model-scheduling.md) | `ScenarioExecutor` 独占模型候选、重试、冷却、授权与计量；每次实际尝试新鲜核权 | Agent 多轮/工具请求仍须经同一网关，不能由 Agno 或供应商 SDK 直连 |
| [CLAUDE.md](../../CLAUDE.md) §1.0 | 默认只读；外部副作用、依赖安装、数据库迁移、部署、消息发送、费用产生须单独确认 | Agent 执行会产生模型费用、MCP 连接、文件导出等外部副作用 |
| [CLAUDE.md](../../CLAUDE.md) §3 | R2 取消传播、R4 SQL 参数化、R9 秘密脱敏、R10 禁止硬编码密钥等不变量 | 新模块必须复用现有取消、凭据、审计与计量机制，不得以框架适配绕过 |

**结论：** 已按 ADR-0016 批准面向**未来新增智能体模块**的有限例外；ADR-0008 对交易、资金、任意代码/命令、核心配置与业务库写入的禁止**保持不变**。

### 2.1 提示注入与净化边界

- 仓库文档、日志、网页、工具/模型输出、MCP 返回资料均为**不可信内容**，不自动成为上级指令；遇内嵌指令只向用户报告，不执行。
- 所有外部文本须经 `utils/prompt_guard.py` 的 `validate_prompt` / `sanitize_prompt` / `neutralize_external_text`，并按 R9 经 `DataSanitizer` 处理后再进入公开历史、摘要、索引、审计或导出。
- 分隔文本、角色标签、XML/Markdown 包裹都**不是安全边界**；最终安全取决于能力不暴露、真实派发门控与结构化权限记录，不能只靠 Prompt 声明。
- 模型输出不能授予权限、扩大数据范围或批准自身工具调用；权限只来自用户/维护者的结构化决定与派发前新鲜核验。

## 3. 已批准的有限例外

仅对**未来新增智能体模块**（主 Agent、subagent、AgentService、Agent 设置与历史）生效，不适用于现有新闻分类、FinBERT 情绪、新闻风险解读、连接诊断或既有选股数学链。

| 例外 | 允许范围 | 必须同时满足 |
|---|---|---|
| E1 资料只读 | 读取用户明确选择的股票/股票池/策略/回测/资讯/附件/历史节点 | 来源、版本、`as_of`、范围、单位与缺失状态可见；PIT/质量检查；不默认读取整库或其他聊天 |
| E2 MCP 只读 | 调用已审核、已授权、语义可判定的 MCP 只读工具 | 服务身份与工具白名单；每次派发核验身份/参数/schema/轮次/资料范围；保存配置不等于连接，连接不等于授权 |
| E3 用户确认导出 | 将已生成的结构化成果导出为 Markdown/CSV/XLSX | 用户通过 UI 选择路径并确认覆盖；固定格式代码执行；Agent 无任意文件写权限 |
| E4 受控持久化 | 应用代码持久化 Agent 历史、原生检查点引用、决定记录、权限与计量元数据 | 由应用服务/DAO 执行，不经模型工具；秘密与隐藏推理不落公开历史/索引/审计正文/导出 |
| E5 固定 stdio 启动 | 用户配置/测试动作明确批准后，由连接管理器启动固定 executable/参数的本地 MCP 服务 | 不经 shell 字符串拼接；Agent 不能改命令或请求任意程序；仅回收本应用创建且记录 PID 的子进程 |

E1—E5 均为**范围化、可撤销、每次派发新鲜核验**的例外，不是一次性永久授权。

## 4. 允许操作矩阵

| 操作 | 讨论/计划 | 执行模式 | 生效边界 |
|---|---|---|---|
| 浏览已存历史/教程、复制可见文本 | 允许，无模型 | 允许 | 不触发任务、模型、MCP 或摘要 |
| 读取用户选中的业务资料/应用附件 | 授权只读 | 授权只读 | 用户范围、PIT、质量、数据量检查 |
| 发送资料给远程模型/摘要模型 | 必须检查外发许可 | 必须检查外发许可 | 讨论/计划不等于零出站 |
| 已审核 MCP 只读工具 | 仅讨论目的所需查询；计划不执行方案步骤 | 获准范围内 | 连接许可与调用许可分开 |
| 用户确认成果导出 | 用户操作触发 | 用户操作触发 | 用户选路径、覆盖确认、固定格式 |
| MCP 本地服务启动 | 用户配置/测试明确发起 | 已获准的固定启动定义 | 不提供 AI 任意命令执行工具 |
| 安装 Skill、编辑设置 | 用户设置操作 | 用户设置操作 | Agent 无配置写权限；安装不执行脚本 |
| 修改业务库/核心配置、交易、任意脚本、下级 Agent | 禁止 | 禁止 | 工具不暴露，执行入口也拒绝 |

补充边界：

- 计划模式只做已授权、用于理解需求的只读查询；不能执行计划中的业务动作。UI 明确区分“生成计划”与“批准启动”，模型文字“建议执行”不构成启动命令。
- 旧公开行情授权仅在同用途、同数据类别、同范围内复用；私人附件、聊天摘要、MCP 返回资料、兄弟任务成果均为新的可判定来源，不自动继承。
- 权限、凭据、工具身份、schema、目标或参数变化时阻止新派发；在途操作仅尽力取消，并如实显示未知结果。
- 无可用 UI 时决定请求保持等待，不自动批准；超时、关闭、Esc、拒绝均不产生授权。

## 6. 明确禁止项

以下能力**始终禁止**，且不属于可讨论的例外：

- 自动交易、下单、资金划转或任何资金相关操作。
- 任意 Shell、终端命令、脚本生成/执行、IDE/代码补全或任意进程启动。
- **未授权的任何外部 API 调用、网络请求、文件写入/删除/重命名**；E3 的固定格式导出与 E4 的应用受控持久化是唯一文件写入例外。
- 写入业务数据库、修改核心配置、修改应用安全设置或绕过既有授权/预算/审计。
- 递归 subagent、多级 Team、由工具或 MCP 间接启动下级智能体。
- 默认 HTTP 服务/端口、云端常驻、多设备同步、外部独立 Agent 协议、技能市场或自动下载更新。
- 将每条新闻或全部模型推理强制 Agent 化；新闻分类、FinBERT 情绪、风险解读与连接诊断保持原路径。
- 无 UI 时自动批准决定、超时自动放行、关闭/Esc 视为同意、旧 Enter/IME 事件穿透为新批准。
- 在未通过 G02/G03/G04/G05 时宣称能力已完成、性能已达标或 41 个 AC 已通过。
- **默认拒绝原则**：未在本文件 E1—E5 明确列出的能力一律禁止；不得以“未列为禁止”推导为允许，也不得以“统一 UI”或“框架支持”扩张权限。

## 7. 审批与生效流程

**本次批准结果：** 2026-11-01 经产品负责人（有权维护者）批准全部建议范围；已创建 [ADR-0016](../adr/0016-agent-permission-exception.md)，ADR-0008 Status 已标注部分替代，文档索引已更新。运行期工具仍未启用，G02/G03/G04/G05 与实现门禁继续有效。以下流程保留为后续变更规则。

2. 审批人填写文末「审批回执」，明确批准范围、排除项、生效条件与复核人。
3. **批准后**才按 [ADR-0001](../adr/0001-record-architecture-decisions.md) 在批准当时分配下一个可用 ADR 编号，编写 `Accepted` ADR，并在其 Status/Decision 中明确对 ADR-0008 的**部分替代范围**；不修改 ADR-0008 的 Context/Decision/Consequences 正文，只按 ADR-0001 生命周期在其 Status 增加 `Partial Superseded by ADR-NNNN（仅 E1—E5 范围；原禁止项继续有效）`，保留追溯。
4. 新 ADR 须同步登记 [docs/README.md](../README.md) 与 [CONTRIBUTING.md](../../CONTRIBUTING.md) 的 ADR 索引，并保持 ADR-0008 与新 ADR 的 supersede 双向链；若涉及红线或架构边界变更，再同步 `docs/governance/redlines.yml` 与 `CLAUDE.md`，并运行文档一致性门禁。
5. 即使 ADR 获批，运行期工具仍须等待 G02 原生可行性、G03 原型评审、G04 契约冻结与对应实现任务通过；本文件不提前启用任何工具。
6. 若审批被拒绝或需重大修订，在本文件记录决定与日期，不创建 Accepted ADR，不占用编号；保留本草案供追溯。
