## 1. 目标、适用范围与闭环

目标是**让错误更难产生、产生后早发现、发现后不能默默进入现行规范、同类错误有可复用回归**，而不是承诺自动证明任意自然语言都正确。

覆盖正式规范、路由、作者源、派生视图、可执行示例、随包操作说明，以及当前设计中被采用的共同合同。草案、历史、评测夹具、外部证据有不同责任，不能混成一个「全部当前有效」的集合；也不能仅凭目录名把活消费者排除。

日常闭环固定为：确定来源和角色 → 识别受影响合同/消费者 → 改作者源 → 同一次解析及生成 → 机器门禁 → 适用语义评审 → 按准确输入交付 → 新问题回流回归。

## 3. 日常编写约束：先避免产生矛盾

1. **先复用再新增。** 先查 topic 入口及事实作者源；新增文件须说明读者目的、独立职责和为什么现有章节不足。不为同一事实再写一篇「新正本」。
2. **区分规范、解释、操作、示例。** 规范规定允许/禁止及适用条件；操作引用规范并给成功/失败/保全出口；示例标明有效模板还是有意反例。解释不能引入另一套义务。
3. **数值与 API 有来源。** 当前可变值引用/生成；历史观测保准确版本；场景示例注明样例口径。金额/数量/缺失/时点仍服从原红线，不通过文档流程降低要求。
4. **绝对语句须有边界。** 新增「必须/只能/禁止」时核正常允许例与最小禁止例，检查是否错误禁止同节示例或既有合法路径。规范修改不能只追加附录，须消除当前摘要中的旧义。
5. **完成条件按触域。** 离线语料不套 Tushare 在线流程；普通配置不被要求新增单位换算；文档已写不要求伪造产品实测；真正触及业务逻辑仍须配套业务单测。
6. **长文靠披露，不靠复制。** 入口只保最低安全信息及到正本的路径；同文只展开一次。缩篇幅不能丢失败分支、许可边界或把未知写成成功。
7. **当前问题不得「历史化免检」。** 历史保留时间语义，但当前会被用户/实现者遵循的操作、作者源或消费者必须修正；迁移前清楚说明当前采用范围。

本节约束以本指南为唯一承载；其它入口只引用，不另写同义清单。

## 4. 六类日常变更的固定操作协议

| 变更 | 写前定位 | 必须联动的输出 | 验收与失败处置 |
| --- | --- | --- | --- |
| 新增文档/topic | 查已有正本；确认正式/草案/夹具角色和负责人 | 新文件独立发现；文件级目录生成；仅真正新任务新增 topic | 新文件未登记或重复 canonical 拒绝；普通补文不强造新 topic ID |
| 修改规则/字段/限额/命令 | 找唯一作者、当前消费闭包与适用画像 | 只改源；生成所有派生；更新解释/正例/操作摘要/完成门中的受影响语义 | 两次生成第二次零差异；不同单位/范围的展示不可简单文本替换 |
| rename/移动 | 保原身份；保存旧/新路径与旧深链 | 改原登记路径、当前引用和正文读取器；必要兼容深链/明确替代入口 | 只查新路径不够；漏消费者拒绝；不靠新 ID 覆盖旧对象 |
| 废弃/删除 | 查当前入链、导入/必读、topic、示例和发布物 | 先指定替代或明确移除能力，再更新消费者/索引；历史保角色 | 尚有当前必需引用则拒绝；旧 snapshot 不回写为新正文 |
| 依赖/API/协议升级 | 绑定准确目标版和已有核验范围 | 复核受影响示例/签名/运行语义；保旧证据；更新当前适用说明 | 旧证据不免新版核验；无环境仅阻相关能力，不伪造全局通过 |
| 实现/CI/能力状态变化 | 先确认真实实现、测试选择和证据对象 | 核合同与实现差异；更新实际当前摘要；保原失败记录 | 代码有变化不由文档自动追认；配置文件存在不证明实际执行 |

通用步骤：建立本次修前基线 → 写影响清单 → 修改作者 → 生成/检查 → 针对性语义与必要运行核验 → 确认实际输入输出 → 当前状态更新。每步失败都保用户稿和原证据，不自动删除、启连或重复派发。

## 5. 影响分析与独立发现：不建第二套关系库

影响清单是**每次检查临时计算的结果**，不是长期手工维护的另一张关系表。输入使用独立发现的交付文件集合、统一解析视图、现有 topic/作者源、静态源码消费及可信 old/new 路径；输出至少区分 `author_paths`、`consumer_paths`、`old_paths`/`new_paths`、`topics`、`test_groups` 和 `unresolved`。

- 有 Git 时用真实差异和跟踪集合，并纳入本次准备交付的新增文件；rename 同时提供旧/新路径。不能只遍历已登记索引，否则新漏登记文件根本不会被看见。
- 归档环境使用准确文件清单/修前副本与明确受管目录；打印发现模式和排除范围。无法恢复旧身份时写「历史身份未验证」，不 `git init` 伪造证明。
- 解析引用、受控块、正文检查、配置引用等关系；必读/导入边用于检查加载环，普通参考/派生回链/历史 ADR 互链不等同死循环。
- 动态消费、条件流程和自然语言关联不能由链接图穷尽；作者补受影响操作入口及适用性，评审者核对其遗漏。图中无边不代表没有语义影响。
- 当前必需源缺失直接失败；具名排除按原作用域处理；历史缺件、外链、HTML fragment、未知 API 分别列结果，不能互相变成「已通过」。

T12/D12 复用既有路径分类与 parser/checker，不引入永久 manifest 数据库、第二 ID 表或「每篇文档一新治理编号」。

## 6. 角色、生命周期与证据适用性

**角色是责任，不是假批准。** 作者提供来源/影响/结果；领域负责人核语义；门禁/CI 维护者核覆盖与执行；QA 核证据和负例；原有权批准者处理权限、例外及风险接受。小项目同一人可兼多个角色，但高风险批准不能由 AI 代签，独立复核义务仍沿原正本。

责任解析顺序：文档已有 owner → 既有 topic 的责任范围 → 本指南默认「架构维护者」。具体人员未指派时记录待指派，由维护者处理，不能伪造姓名/批准；涉及权限/例外审批的工作不因默认 owner 而获得批准。责任只在作者处维护，目录/平台配置引用或派生。

生命周期分两轴，不混成一个「已完成」：

- **文档角色/效力：**草案、已采用合同、现行参考、历史、派生、评测夹具；同名或日期新不能自行升效力。角色从文件自身声明/已确认采用关系和具名范围取得；矛盾或未知显式诊断。
- **验证状态：**未验证、部分验证、在指定范围已验证、不适用。已采用合同仍可以未实现；不适用必须有条件，不以空集合偷换。

活动条目至少可定位主题/当前作者/角色/负责人/替代目标；版本敏感证据另携目标版本或输入 hash、日期、环境、范围、命令、结果和限制。普通说明无需为每次标点修改填完整证据表。真实复核日期独立记录，不同步一组文件的日期。

证据在目标、版本、影响范围或关键执行环境改变时须重评适用性；原记录保留，不覆盖成新版 PASS。历史 ADR 的 Decision 保留，替代范围写新决策；部分缓解只关闭相应子项，残余沿现有技术债，不恢复已退役 findings 登记。

## 7. 自动检查、语义评审与执行验证的分工

| 层 | 能认证什么 | 不能认证什么 | 触发方式 |
| --- | --- | --- | --- |
| 结构/作者源/派生 | 语法位置、路径/锚点、独立发现、字段/schema、块唯一、来源方向、再现性、非空 | 任意自然语言的业务含义、批准真实有效 | 每次变更，轻量环境 |
| 静态源码/配置接线 | 声明身份、实际选择命令与候选消费、受控函数/配置范围 | API 真实签名、分支必达、远端强制 | 源码/门禁/选择变化，保必要基线 |
| 锁定 API/应用示例 | 实际导入/签名及选定示例行为 | 产品数据、恢复/外部效果、读屏和性能 | 相关规范/依赖/API 变化，应用隔离环境 |
| 语义评审 | 条件、允许/禁止例、单位/时点、正文摘要、操作失败分支、来源/采用范围 | 通过评审替代未知运行事实 | 变更影响闭包；权限/红线/跨层由有权角色和原独立规则 |
| 实际执行/平台/产品 | 指定目标、环境、命令及结果，真实 required/用户验收 | 对其它版本/目标或未测范围作保证 | 相应实施、上线或发行门，单独许可 |

语义评审交付的是逐条证据核对，不是「LLM 评分一致所以正确」。至少回答：作者源是否唯一、适用条件是否一致、正例是否合法、禁止例能否阻断、成功/失败出口是否保全、摘要是否遗漏重要限制、证据是否适用；未核项列范围和下一步。

普通措辞/链接修正只做其影响范围，不要求每次重读全仓全部文档。涉及 R20/R21/R24 等产品结论仍沿原独立复核，不由文档治理流程代签。

## 8. 失败分级、阻断范围与安全边界

- **确定当前错误：**非法作者源、悬空必需消费、重复生成块、错误操作/权限语义、所需测试失败等，阻断相应交付；修根因后重验，不能改成 warning 凑绿。
- **当前必需检查未完成：**缺实现/依赖/环境/审批/参与者，标未运行或受阻；其它独立检查可以完成，但聚合不得声称全部通过。
- **历史/范围外记录：**保原字节、日期、base 及限制；按具名规则处理。不能成为默认当前正本，也不把全部历史缺件强加给无关修复。
- **只表示建议的 warning：**沿原 CLI/真实仓库基线分层；某层退出 0 不代表下一层通过。每条需说明影响，不新增泛禁编号、日期、数值或全文件规则。

例外续效按 **AND 谓词**（ADR-0018 C15）：仅在原范围及全部必要前提均未变，**且所有已声明的退出条件均未触发**时沿用——有 `expires_at` 须未到期，有 `removal_trigger` 须未满足；同时声明时两者都须成立，不能用 OR 续效。触发后由原 owner 核并停止在受影响变更中使用，不能自动续期。本指南的判断不自动撤销连接、改配置或关闭运行中的应用。

检查/生成默认不联网、不读秘密、不执行文档内代码/HTML、不写作者源。依赖安装、远端策略修改、真实外发、数据库/发布操作按原授权。不能借长期维护设常驻 Agent、自动提交或批量破坏性「恢复干净」。

## 9. 触发复核与低成本周期维护

**随变更检查优先于定期大扫除。** 以下为选定的运行节奏，属于本维护合同，不是当前已经开启的定时任务：

| 时机 | 检查范围/责任 | 产出与退出条件 |
| --- | --- | --- |
| 每次交付 | 作者/领域负责人核实际变更闭包；机器门禁按仓库既有门禁执行 | 当前变更证据与未核范围；不重写其它文档复核日期 |
| 来源、规则、依赖、API、协议或 CI 变化 | 原 owner 核受影响合同/示例/目标及证据适用 | 有证据才更新当前结论；过期旧证据保历史 |
| 每月一次 | 架构维护者检查活动例外到期/移除条件、待指派 owner、未处理的当前冲突、发生变更的证据适用性 | 处理结果写原例外/债目/任务；无变化只记录已查范围，不重审全仓 |
| 每季度或相关发行前，择一避免重复 | 门禁维护者/QA 执行第 11 节受控演习，核必要 job 和所用平台能力 | 原回归留测试；平台不可用记未核，不能以本地模拟签远端强制通过 |

不新增 cron/数据库/提醒服务。初次演习执行（T13/D13）记录实测成本和阻断原因；后续超出可维护成本时缩无价值重复检查，不删除必要安全保证。无需每月统一递增规则集版本或批量触碰无变化文件。

**例外移除条件的季度人工判定（不由 checker 代替）**：每季度逐条判断 `docs/governance/exceptions.yml` 中已声明 `removal_trigger` 的例外其触发条件是否已满足；已满足者按 C15 停止续效，并在 `exceptions.yml` 中登记移除该例外，或在原例外重新批准续期。`check_exceptions_effectiveness()` 只校验 `expires_at` 的日期合法性与是否过期、以及 `expires_at`/`removal_trigger` 字段完备性，不判自由文本条件是否成立——该语义判定必须由人工完成并留记录。

**记录落点（LA15）**：上述每月/每季复核与例外判定，处理结果写入原例外条目（`docs/governance/exceptions.yml`）、`docs/debt/known-technical-debt.md` 对应条目或本次 PR 描述。`Plans.md` 与 `reviews/` 下的检视产物属本地台账（gitignored），**不得作为唯一记录**。无变化时只记录已查范围与日期，不重写其它文件的复核日期，也不为记录新建登记平台或提醒服务。

## 10. 新问题回流与门禁的长期维护

1. 接到发现先区分当前缺陷、历史观察、语义未知和检查器误报；按实际影响定级，不按 R 标签自动 P0。
2. 找对应 L 根因族及已有作者/检查/测试。把合法入口和单一变因做成反例；同时保允许例和已知空 stub 等反证。
3. 修作者源、生成/解析或实际实现的根因；同类消费者一起修，不只改报错文本。
4. 原反例 RED→GREEN 后加入现有测试；新检查声明输入、覆盖、执行入口、运行环境和失败语义。静态名字/AST 调用只记接线证据，实际回归另证执行。
5. 未关闭的真实残余放原技术债/任务；原证据留在会话或检视产物，不再建第二永久 findings 库。新问题不直接升级成新红线，确需新规则按原治理流程批准。
6. 移除旧检查须有等价承接、旧反例仍失败和允许例仍过；新控制若仍要求多份手写数值/状态，优先修来源或生成，而不是增加同步守卫。

成功指标是单源更新可再生、真实非法变更能拒绝、合法维护不过度阻断、覆盖/未知准确且成本可记录；不是检查数量增长、文件变短或全文 grep 零命中。

## 11. 受控维护演习与长期交接（E01—E12）

> **本表为测试合同，不是通过记录**：E01—E12 必须在临时夹具/获授权隔离工作区运行真实检查入口执行（T13/D13），不能直接改生产规则造反例；在演习实跑并记录之前，不得声称任一案例「已通过」。

| 案例 | 允许维护 | 单变因负例 | 预期结果 |
| --- | --- | --- | --- |
| E01 | 新正式文件可独立发现并进入文件级目录 | 仅漏目录登记，或两个 canonical 作者冲突 | 正例过，负例拒绝；草案角色不误升效力 |
| E02 | 作者处改合成限额，派生一致；负责人核单位/范围 | 只改一处 UX 副本；或两副本一致但无作者关系 | 不认证无来源值；只改一次源，二次生成零差异 |
| E03 | 原身份 rename，旧/新路径和消费者都迁 | 只检测新路径、遗留旧深链 | 旧消费遗漏明确失败，不另造新 R/topic 身份 |
| E04 | 先迁消费者再删旧规范 | 仅删必需源/活模板，使提取集合为空 | 直接缺件/非空失败，不能依其它检查偶然兜底 |
| E05 | 新目标版配其准确 API 证据 | 旧版 PASS 或另一 variant 认证当前版 | 标过期/未核，不写当前已验证 |
| E06 | 合法 reference/HTML ID/重复标题/两类围栏/行内代码 | 仅造真死链，或示例标题补必需正文 | 合法语法不误报；真缺件/正文缺结构失败 |
| E07 | 固定受控块生成且作者/手写正文保真；外部编辑在保护边界内可靠串行化 | 第二重复块、嵌套块、越界、中断；或渲染后、提交核对后但替换前编辑目标正文/作者源 | 冲突或保护不支持时非零，保留用户新稿并列已写/未写；受阻写者的后续编辑也保留，无旧快照覆盖或假回滚 |
| E08 | 活示例被选择；有意空 stub 保持允许 | 测试不被选择、零提取或假迁移标记绕过 | 活保护不能空转；stub 不误阻 |
| E09 | 所需 job 成功；其它 job 按显式条件合法 skip | 所需失败/取消/skip 或探测缺失 | 聚合不能绿；只读模拟不认证远端状态 |
| E10 | 原例外范围/必要前提成立 | 到期、范围已变、移除条件已触发或无批准依据 | 不自动续效/扩大；未核批准不得报有效 |
| E11 | 文档已采用/静态绿但产品未测明确分层 | 提示代替加密、安装代替 CUX、报告代替 PG/发行 | 不关真实剩余门；不谎称产品完成 |
| E12 | 有条件规范配合法命令/操作例，成功与失败都保全 | 正文禁掉同节允许例，或摘要删停止未知保全分支 | 适用语义评审拒绝；自动检查不足时明确人工发现 |

演习先核合法基线，逐个注入负例，确认失败原因，再恢复并重验；真实业务/API/远端能力仅在其环境与授权具备时另核。归档可完成受控文件/CLI 演习，不冒充 worktree 或 GitHub 强制。

交接至少覆盖一次新增、一次作者源修改、一次 rename/删除及一次证据失效处置；维护者从本指南找到来源、判断影响、运行检查、解释失败和当前状态。无需记住所有文件关系；无法完成的步骤回原任务/owner，不能把「文档已写」记作长期能力成熟。
