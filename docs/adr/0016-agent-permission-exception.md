# ADR-0016: 智能体有限权限例外与允许操作矩阵

> Status: Accepted
> Date: 2026-11-01
> Owner: 架构维护者
> Supersedes: ADR-0008（部分替代：仅未来新增智能体模块的 E1—E5 有限例外；原禁止项继续有效）

## Context

[ADR-0008](./0008-no-ai-execution.md) 当前规定 AI 输出仅用于评分和文本展示，禁止触发交易/资金、调用外部工具、生成或执行代码、修改核心配置或数据。该约束消除了整类安全风险，仍是现有新闻分类、FinBERT 情绪、新闻风险解读、连接诊断与既有选股数学链的有效边界。

内部需求基线（本地存档，不入库）要求未来新增智能体在用户授权范围内完成资料只读、已审核 MCP 只读调用、用户确认导出与受控历史持久化。若直接沿用 ADR-0008 的绝对禁止，这些已确认功能无法实现；若放宽为通用工具权限，则会破坏 ADR-0008 的核心安全收益。

因此需要一份**范围化、可撤销、每次派发新鲜核验**的有限例外，并保留 ADR-0008 对交易、资金、任意代码/命令、核心配置与业务库写入的禁止。

## Decision

1. **采用详细契约**：[docs/architecture/agent-contract.md](../architecture/agent-contract.md) 作为本 ADR 的操作矩阵、RR01—RR05/D01—D10 批准值与审批回执载体；其内容与本 ADR 冲突时，以本 ADR 与需求基线为准。

2. **仅适用于未来新增智能体模块**：主 Agent、subagent、`AgentService`、Agent 设置与历史。现有新闻分类、FinBERT 情绪、新闻风险解读、连接诊断、既有选股数学链与夜间业务触发**不因本 ADR 获得 Agent 工具执行能力**。

3. **批准以下有限例外，且必须同时满足所列条件**：

   | 例外 | 允许范围 | 必须同时满足 |
   |---|---|---|
   | E1 资料只读 | 用户明确选择的股票/股票池/策略/回测/资讯/附件/历史节点 | 来源、版本、`as_of`、范围、单位与缺失可见；PIT/质量检查；不默认读取整库或其他聊天 |
   | E2 MCP 只读 | 已审核、已授权、语义可判定的 MCP 只读工具 | 服务身份与工具白名单；每次派发核验身份/参数/schema/轮次/资料范围；保存配置、连接、授权三者分离 |
   | E3 用户确认导出 | 已生成成果导出为 Markdown/CSV/XLSX | 用户通过 UI 选择路径并确认覆盖；固定格式代码执行；Agent 无任意文件写权限 |
   | E4 受控持久化 | Agent 历史、原生检查点引用、决定记录、权限与计量元数据 | 由应用服务/DAO 执行；秘密与隐藏推理不进入公开历史/索引/审计正文/导出 |
   | E5 固定 stdio 启动 | 用户配置/测试动作明确批准后启动固定 executable/参数的本地 MCP 服务 | 不经 shell 字符串拼接；Agent 不能改命令或请求任意程序；仅回收本应用创建且记录 PID 的子进程 |

4. **RR01—RR05 与 D01—D10 按 [agent-contract.md](../architecture/agent-contract.md) §5 的批准值生效**：显式模型不暗备、会话占位与推理许可分离、入队冻结意图/版本、稍后不批准/不终止、程序持久业务身份；只读查询与用户确认导出、本地目录/ZIP 技能、stdio + Streamable HTTP、单机当前用户、D05 限额、D06 附件范围、D07 导出格式、D08 摘要系统连接、D09 历史生命周期、D10 性能目标均按该表演进，调整须另立决策。

5. **默认拒绝与净化**：未在 E1—E5 明确列出的能力一律禁止；不得以“未列为禁止”推导允许。所有外部文本须经 `utils/prompt_guard.py` 的 `validate_prompt` / `sanitize_prompt` / `neutralize_external_text`，并按 R9 经 `DataSanitizer` 处理；分隔文本、角色标签、XML/Markdown 包裹不是安全边界。模型输出不能授予权限、扩大数据范围或批准自身工具调用。

6. **始终禁止**：自动交易/下单/资金划转；任意 Shell/终端命令/脚本生成执行/IDE/代码补全/任意进程；未授权的外部 API/网络请求/文件写入/删除/重命名；业务数据库、核心配置或应用安全设置写入；递归 subagent、多级 Team 或经工具/MCP 间接启动下级智能体；默认 HTTP 服务/端口、云端常驻、多设备同步、外部独立 Agent 协议、技能市场或自动下载更新；无 UI 自动批准、超时放行、关闭/Esc 视为同意、旧 Enter/IME 事件穿透为新批准。

7. **生效门禁**：本 ADR 的批准不等于运行期工具已启用。工具、MCP 连接、导出、持久化与 UI 能力仍须分别通过 G02 原生可行性、G03 原型评审、G04 契约冻结、对应实现任务与 G05 发布验收；在 G02 通过前不得启动产品实现。

8. **模型治理不变**：[ADR-0014](./0014-unified-model-scheduling.md) 继续有效；所有模型请求仍经 `ScenarioExecutor` 的候选、逐次授权、预算、审计与计量，不引入第二 Router、供应商 SDK 直连或第二账本。

**批准记录**：有权维护者（产品负责人）于 2026-11-01 明确批准“全部建议范围”（E1—E5 与 RR01—RR05/D01—D10 建议值）。该批准只覆盖本 ADR 的权限例外与决策值，不构成 G02/G03/G04/G05 通过，不启用任何运行期工具。

## Consequences

- **正向**：未来智能体可在明确、可审计、可撤销的范围内完成资料只读、MCP 只读、用户确认导出与历史持久化；ADR-0008 的高风险禁止项继续有效；权限范围、数据范围与模型治理有长期可追溯依据。
- **负向**：每次派发需核验身份、凭据、目标、工具 schema、资料范围与轮次，增加实现与测试复杂度；用户会看到更多授权/澄清提示；MCP/导出/持久化的故障路径增多。
- **缓解**：以 `services/agent_service/policy.py` 作为唯一派发许可边界；决定服务使用原生 requirement 与 CAS 至多一次消费；历史/索引/审计统一脱敏；故障注入覆盖撤销、参数变化、未知回执与非幂等调用；G02—G05 分别取证，不以单一示例或 Mock 替代。

## Alternatives

- **维持 ADR-0008 绝对禁止**：拒绝。会使已确认的 F33/F34/F36 等能力无法实现，需求基线不能静默删减。
- **放宽为通用工具/代码执行权限**：拒绝。直接违反 ADR-0008 的核心安全收益与需求基线 D01。
- **在 Agent 外自建第二套权限/调度/计量系统**：拒绝。重复既有治理，增加长期维护与故障边界，违反 ADR-0014 与 BR13。
- **仅按每次请求临时批准、不落 ADR**：拒绝。缺乏长期追溯、范围复用与撤销规则，无法支撑跨会话/API 的一致性。
