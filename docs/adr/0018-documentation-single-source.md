# ADR-0018: 文档体系单写入源与长期治理（Documentation Single Source）

- 状态：已接受（Accepted）
- 日期：2026-11-13
- 决策人：架构维护者
- 关联：ADR-0002（文档分层）、ADR-0006（AGENTS 最小安全集 + 指针）、ADR-0014（统一模型调度）、ADR-0016（智能体权限例外）；来源检视文档 `reviews/文档体系检视与改进.md`（仓库未跟踪的工作稿，其相对路径以仓库实际位置为准）

## 背景与问题（Context）

文档体系检视（来源文档第 2 节 F01—F22 问题族，证据索引见其第 8 节）确认四类系统性偏差：**双写事实**——同一规则/清单在多处手工维护，改一次源需要多处同步，漂移由门禁兜底而非结构消除；**规范与示例互斥**——复制文档示例即违反该文档自身的规范；**旧状态冒充当前**——历史轮次的安装/授权/完成摘要复活为当前结论；**多套解析**——一致性校验从全文任取样例、宽松匹配导致假绿，真实死链与失踪输入反而放行。这些不是单点笔误，而是「没有唯一写入源 + 消费者各自维护副本」的结构性后果。本 ADR 承接检视文档第 3 节 C01—C15 已确认裁定与第 4 节单写入源结构，作为后续工作包（T1—T10）的实施依据；裁定内容为**无备选的已确认决策**，不存在「以后决定」或「在若干方案中再选择」的开放项。

## 决策（Decision）

### a) 单写入源目标与切换条件

按来源 §4.1「唯一作者源与派生目标」逐行记录目标权威关系：

| 内容 | 唯一写入源 | 生成或引用目标 |
| --- | --- | --- |
| 全局行为、语言、授权底线 | AGENTS 精简手写正文 | CLAUDE 单向导入，普通链接只供人工发现 |
| 文档长期编写、变更与维护流程 | documentation-maintenance 维护指南 | CONTRIBUTING / governance README 只保入口；任务路由引用，不再复制完整流程 |
| R 身份/标题/判据/类型/coverage/self_check | redlines.yml | governance 规则参考、AGENTS 最小安全集；旧 CLAUDE 表/摘要/self_check 消费者迁往新目标 |
| 例外范围/有效/移除/批准 | exceptions.yml | 专项只引用 EX 条目，不手写另一份原因 |
| 任务身份和入口 | canonical-topics.yml | AGENTS 任务表与 governance 路由表；按相同 canonical/section 合并展示，保全部 topic ID |
| 架构正文 | architecture/overview.md | 专项/任务入口引用，import-linter 配置仍是实际执行配置 |
| 最小验证命令 | CONTRIBUTING 受控块 | AGENTS 命令视图；专项只指出适用子集 |
| 正式文件发现信息 | 文件自己的标题/明确角色 | docs/README 按文件生成；删除其他入口的全目录副本 |
| 产品版本/marker/运行配置 | pyproject 与实际配置 | 生成必要参考，历史观察保精确版本，不写当前副本 |
| 规则集版本与实质期限 | ruleset-changelog 最新已确认记录 | T6 完成来源/消费者切换时登记规则集 1.10.0；此前仍为 1.9.0，不先改日志制造旧元数据门禁失败；产品版本不变 |
| 对比度数值/覆盖 | check_theme_contrast 既有常量/色对 | accessibility 基线受控块；不重新定义另一组阈值 |
| Agent 共同字段、身份与 wire | 当前 DD 公共合同 | HANDOFF 引用/接线摘要生成或精确一致性校验；不同 UX 角色不互拷 |
| 当前债目状态 | known-technical-debt.md | 专项链接当前残余；历史报告保修前事实 |

**上表为切换目标，不是立即生效的正本变更。** 在 T6 消费者迁移与等价检查通过之前：现行 CLAUDE.md / AGENTS.md 的权威声明（含「主题权威来源」表、生成区块守卫）、既有深链与检查继续保留；不因本 ADR 先行修改 redlines.yml / canonical-topics.yml 的正本声明或规则集版本（保持 1.9.0），不先删旧表、不改必读路径、不放弃旧守卫（来源 §4.3 第 1 条）。同源约束到「事实/字段」层面，不是整个领域强制收敛到单个文件；治理 ID 历史对照保留，R/EX/ADR 及明确规则引用继续校验。

### b) C01—C15 裁定逐条承接

以下 15 条为检视文档第 3 节已确认执行规则，本 ADR 全部承接为既定决策；「归属工作包」按来源 §6.3 的唯一归属：

| 裁定 | 内容摘要 | 归属工作包 |
| --- | --- | --- |
| C01 事件与水位 | 事件行用 `session_seq`/`execution_seq`，所属 session/execution 的 `event_seq` 仅是已提交水位；HANDOFF 事件键改为 `execution_seq`。不迁现有水位列、不新增事件表 | T7 |
| C02 命令身份 | 意图 = `business_request_id`；请求客户端键 = `client_command_id`；持久引用/回执 = `command_record_id`。按用途逐处更名，禁止全局替换或请求方伪造 PK | T7 |
| C03 切片准入 | 真全局安全前提保留；特定预算/协议/制品证据只阻依赖切片。旧综合冻结不改成已完成；整体结束仍需全部必要门 | T7 |
| C04 目标状态 | 旧 runner/安装原因按历史记录，当前 target/variant/工具配置单独核验；安装授权不能关闭 CUX 或产品门 | T7 |
| C05 模式边界 | discuss/plan 的研究取数、检索、MCP 研究调用、研究叶子派发均为 0，即使已有授权。已准备资料、受治理模型回答/摘要、原控制和显式管理操作按原权限分别核验 | T7 |
| C06 SSE 范围 | stdio/Streamable HTTP 保持默认；首版保留用户显式选择的旧 HTTP+SSE 兼容。保存不连、默认不选 SSE、不自动切协议/重连；支持必须有协议回归 | T7 |
| C07 计划状态 | plan 是成果类型，未启动/排队/运行/终态来自关联执行事实；未知关联显示未知。启动所审版本是新意图，重传不能重复启动 | T7 |
| C08 备份角色 | 备份冻结字节和原相对 base；不继续充当接线正本，不回写当前字段。当前附件与 Cursor 的不同消费角色保留，共同合同只定义一次 | T7 |
| C09 备份债务 | 提示交付只关提示子项；未加密残余保留。不接受「任一启用即整体关闭」，不新增加密实施任务 | T2 |
| C10 阈值语义 | 不建立全局 100ms 同步 IO 豁免；阻塞性质/事件循环路径/不可控依赖决定搬迁，`PerfThreshold` 仅慢操作告警。删除 profile 对未定义全局阈值的背书 | T2 |
| C11 R3 覆盖 | 当前不签 full，规则仍禁止裸 ignore；修覆盖与 `.pyi` 现状说明，coverage 升级只能由实际回归证明 | T5 |
| C12 重试路线 | 维持 ADR-0014 的 Tenacity `AsyncRetrying` 路线和原次数/退避/Retry-After/deadline/逐次授权计量。自管偏离不追认；定向迁移必须保持行为回归 | T8 |
| C13 草稿归属 | 不新增 `ModelManagementDraft`。现成清单明确 UI 的 `ModelConnectionDraft` 及服务 JSON mapping/CAS 边界；frozen 发布/执行类型要求保留。草稿不属于该现成 core 清单，由本 ADR 说明 | T2 |
| C14 取消边界 | 协作 flag 可保 `SyncResult(cancelled)` 统计；真正 `CancelledError` 清理后 raise。任务提交适配必须将协作取消映射为取消，不能正常返回后被 TaskManager 算 COMPLETED；TaskManager 不硬编码全部业务类型 | T8 |
| C15 例外谓词 | 原获批偏离前提仍成立 **AND** R5 对应范围未变 **AND** 未触发该条移除条件，三者全部成立例外才有效；任一必要前提失效或触发移除即停止沿用，不扩展到新方法/新服务 | T1（本 ADR + exceptions.yml 落地） |

**C15 固化为例外有效谓词规则**：exceptions.yml 中 R5 例外条目（EX-0017、EX-0018）的有效性判据（`validity_criteria`）改为 AND 语义——原获批偏离前提仍成立、R5 对应范围未变、未触发该条 `removal_trigger`，三者必须全部成立才可沿用；任一失效或触发移除即停止沿用，且例外仅限既有方法/流程范围，不扩展到新方法/新服务。本 ADR 发布时该谓词已在 `docs/governance/exceptions.yml` 的 EX-0017/EX-0018 落地（本 ADR 同批变更）。

## 后果（Consequences）

**迁移次序**（来源 §4.3，失败保全为各步约束）：

1. **先承接语义，不先缩入口**：本 ADR 记录目标权威关系与切换条件，并修正 EX-0017/0018 有效谓词；T2 承接 F01—F16 现行正文。现行 CLAUDE/AGENTS 的安全内容、深链及检查继续保留，直到 T6 消费者转换与等价检查通过。
2. **再建立可验证派生**：T3 准备解析/纯文档测试，T4 实现生成与旧 CLI 兼容，T5 逐项转换原检查；任一旧检查退役前，正常样例、原失败样例和迁移后的等价失败样例都必须运行。
3. **然后切入口**：T6 迁移全部当前链接、正文读取器、章节断言及 harness 权威引用后再精简 CLAUDE/AGENTS；旧锚点保兼容定位或改到新目标。
4. **独立工作不等待无关生成**：T7 依赖 T2 语义承接，不等待 T6；T8 依赖本 ADR 正式裁定与相应规范，不依赖 Markdown 解析器。
5. **最后切 CI 与交付**：T9 在新旧本地检查等价、纯/应用测试隔离成立后切 CI；T10 收全包证据。

**失败保全**：保留仍可用的旧入口和守卫；逐文件列出已修改/未修改清单；不自动回滚用户改动、不清空输入凑绿。迁移期间由同一作者源生成必要兼容视图，只有旧消费者全部迁走后才移除兼容视图，不要求双边手工维护。

**生效面**：本 ADR 不直接改变任何运行时行为；其可判定产物为 EX-0017/0018 的 AND 谓词（已落地）与 C01—C15 的归属表（约束后续工作包交付去重，不免除其它消费者的承接责任）。

### 实现偏离登记（DEV-01 / DEV-02）

以下两处为当前实现对本 ADR §5.2 合同的有意识偏离，在此登记以保留「偏离原因 + 已知上限 + 升级触发」，避免被误读为已满足全部原子/保护语义：

- **DEV-01：更新后 all 检查在保护释放后执行**（`scripts/docs_generated.py::run_update` 步骤 9）。原因：Windows 独占写入保护期间任何新开句柄读取均被拒（实测 `PermissionError`），而 42 项检查函数全部经新句柄直读文件。已知上限：未完全满足 §5.2.1-2「更新后 all 检查处于同一保护边界内」。边界：写入窗口（读快照 → 预校验 → 逐文件提交替换）仍由独占保护完整覆盖，不以事后检查补救已丢失正文；释放后至检查期间的并发编辑由检查自身内容比对 fail-closed（退出 1）。**观测差异（E07）**：因保护实际覆盖外部写者，窗口内注入的外部编辑本身被拒绝（`PermissionError`），故 §9.11 E07「用户新稿窗口保留」在本平台的可观测形态是「原稿逐字节不变 + 冲突如实上报」，不存在「新稿已落盘再被保留」的中间态；`tests/docs/test_e01_e12_drills.py::test_e07_edit_in_protection_window_conflicts_and_preserves_original` 按此严格断言，不以后者冒充前者。**升级触发**：① 保护机制支持共享读（句柄继承/共享锁），或 ② 检查函数改为复用写者已持有 fd 或共享解析视图后，须将 all 检查移入保护窗口；在满足其一前，不得宣称 §5.2.1-2 全满足。
- **DEV-02：目标写入用 `ftruncate` + `write` 原位写，非「临时文件 + `os.replace`」原子替换**（`scripts/docs_generated.py::_ProtectedTargets.write_bytes`）。原因：原子替换会更换文件身份（`st_dev`/`st_ino`），使已持有的独占句柄与目标身份脱钩，Windows 上无法对未替换目标保持独占。已知上限：不承诺崩溃原子性——进程在 `ftruncate` 后、`write` 前崩溃会留下截断/半写文件（本就无跨文件事务）。边界：截断与写入发生在已核对快照且持独占保护窗口内，外部写者被阻止。**升级触发**：① 引入不破坏句柄身份的崩溃一致原位写方案（平台原子覆盖 API / WAL），或 ② 放弃独占句柄保护改为临时文件 + 替换；在满足其一前，不得宣称「写入中断可原子回滚」。

## 备选方案（Alternatives）

以下各项已在检视文档 §1.1 固定范围与 §11 落地授权中否决，记录否决理由；本 ADR 承接的 C01—C15 均为已确认裁定，**无未决备选**：

- **建设文档网站 / 第二套泛注册系统**：否决。现有目录增量修复即可承载单写入源；另建注册平台会引入新的双写面与维护成本，与「消除双写」的目标自相矛盾。
- **新增 `ModelManagementDraft` 草稿类型（C13 相关）**：否决。现成 core 清单已覆盖 `ModelConnectionDraft` 与服务 JSON mapping/CAS 边界；无调用方的草稿类是死代码，frozen 发布/执行类型要求保留即可。
- **批量迁移旧原型 / 重写全部业务模块**：否决。超出文档治理范围，回归责任无法在纯文档改动中承接；既有 patterns/flet/guides/debt 与 Agent 材料位置保留，先修内容和引用。
- **恢复 Tenacity 契约与取消任务适配藏入纯文档改动**：否决。二者属定向代码修复，回归责任已在任务表固定（T8），不得藏在文档任务中蒙混通过。
- **不加密备份、不接受「任一启用即整体关闭」（C09 相关）**：否决新增加密实施任务；提示子项与未加密残余分别结案。
- **隐含授权**：否决。方案批准不等于实施、安装、外部操作或测试通过；秘密读取、外送、真实业务数据库、迁移、费用调用、部署/发布等须单独许可（来源 §11）。
